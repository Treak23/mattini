## The known items

- **K1: confirmed, a defect, P1 (F1).** `main.gd:479` sets `_camera.height_at = _ground_height` only inside `_show_terrain`. `main.gd:628` returns `_terrain.data.get_height(...)`. Terrain3D returns NaN outside its regions and at holes: this is pinned by `game/tests/test_terrain_loader.gd` (lines 96-117: holes and outside_regions "no height"; not run by me). `free_fly_camera.gd:110-115` does nothing when the ground is not finite, and `test_free_fly_camera.gd:89-91` pins that "free where there is no ground". Nothing bounds the camera to the 2 km × 3 km box. The far chunks use `CULL_BACK` (`surroundings_loader.gd:38`), so a camera that enters a mountainside sees the ground disappear.
  - Likelihood: high. Default speed is 30 m/s, 150 m/s fast and up to 1000 m/s; the box edge is 1 to 1.5 km away; the valley walls rise within a few km. Flying toward the Matterhorn at the start altitude passes through the far mesh.
  - The box-edge sub-case is real but smaller. The clearance is 1.5 m (`free_fly_camera.gd:21`), not 2 m, and the 50 m mean differs from the 0.5 m ground by metres only in gullies and convex ridges.
  - Smallest fix: `SurroundingsGrid.height_at(x, z)` evaluated on the loader's own triangles (NE-SW diagonal; NaN in the cut or outside the box), kept in main.gd as `_far`. `_ground_height` returns the near height if finite, else the far height, null-safe for both. Set `_camera.height_at` whenever either is built, not only in `_show_terrain`. Files: `game/scripts/terrain/surroundings_grid.gd`, `game/scripts/main.gd`, plus GUT tests.
  - Not proven by me: the visual effect (no render).
- **K2: confirmed (F3), P3.** Seven call sites in six files use `length() == 64 and is_valid_hex_number()`: `tree_chunks.gd:319`, `building_chunks.gd:190`, `surface_grid.gd:281` and `:324`, `terrain_grid.gd:212`, `shadow_grid.gd:372`, `photo_grid.gd:200`. Godot's `is_valid_hex_number()` accepts a leading plus or minus, so `"-" + 63 hex` passes the shape check.
  - Today, for the compared digests (terrain, buildings, trees' chunks, photo, surfaces and shadows `sha256`, the surfaces' and shadows' decoded pixels), the later `found != digest.to_lower()` refuses it. The remedy named is right, but the wording is a hash mismatch rather than "must be 64 hex digits".
  - For the shape-only fields (`photo.pixels_sha256`, the trees' surface-tile `sha256`, `shadows.source.entry_sha256`) a signed value is accepted silently and never used.
  - No wrong data is ever accepted.
  - Fix: one helper, a char loop as `surroundings_grid.gd:540`, in `ManifestValue`, used at the seven sites, with a test per reader.
- **K3: partly confirmed (F2), P2.**
  - Code: `_published_asset` calls `fetch_json(item_url)` once (`download.py:1246`), and `urllib_fetch_json` (`:1138`) has no retry. An OSError, HTTPException, truncated JSON or HTTP status other than 404 becomes a refusal. File fetches do have `ATTEMPTS = 2` (`:142`, `_fetch_verified` `:1303`).
  - `download farphoto` always reads all 1806 items before any file (`_download_tiles` calls `published_farphoto` first), and 586 of them are 404s.
  - Record: resets at brief 05 (lock), 05 and 06 (download). The 06 record says the agent proxy logged `server_draining`, so the observed rate is the sandbox proxy's, not shown for a GitHub runner. The session's own note says the dry run is what measures it.
  - Likelihood of a failed Release build: real but unmeasured. The consequence is a re-run of the whole workflow (all seven downloads, tlm 2.9 GB included, on a fresh runner), and never wrong data: no draft is created before the last step.
  - One retry per read is safe for determinism if it retries only connection errors, truncated bodies and HTTP 429 and 5xx. It must never retry a 404 (that is the answer "absent"). The retried read goes through the same checks: id, datetime in the pinned edition, exactly one asset, checksum parse, then the lock comparison. A retry can only turn a transient refusal into the same success. `_in_parallel` still raises the first failure in cell order. A short sleep is needed because a draining proxy resets again at once.
  - Fix: loop `ATTEMPTS` in `_published_asset`, testable with a fake `fetch_json` that fails once.
- **K4: confirmed (F4), P3.** `surroundings.py:600` and `farcolour.py:404` are unreachable by construction. Before them, `check_surroundings_config` (exactly one area with margin and spacing), `_regio_config` and `_far_config` (the entry and an `edition` text), and the `area in world.areas` refusal make every `DownloadError` path of `fit_problem` (`dataset_of`, `edition_of`, `surroundings_margin_spacing`) impossible. The comments there ("a datasets config fit_problem cannot read") and the docstring at `surroundings.py:593` describe a conversion that never happens. Reachable and needed only in `manifest._inputs_check`.
