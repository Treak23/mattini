## New findings

### N1 (P3): the checksum instruction fails for a single download
`release_notes.md:45-46` tells the player to run `sha256sum -c SHA256SUMS`. SHA256SUMS lists both platforms, so a player who downloaded only one archive gets FAILED lines and exit 1.

Measured: with one listed file missing, plain `-c` printed "FAILED open or read" and exited 1. `--ignore-missing` printed OK and exited 0.

**Fix:** use `--ignore-missing`, and give a Windows command (certutil or Get-FileHash).

### N2 (P3): "built from main" is not checked
`release_notes.md:1` claims the build is "built from `main` commit @SHA@". `release.yml` checks only that the sha is 40 hex digits and that the checkout matches it, not that the sha is on main.

**Fix:** add a `merge-base --is-ancestor` check against origin/main, or reword to "commit @SHA@".

### N3 (P3): RELEASE.md and the plan still describe the old route
- RELEASE.md §A (:20-27) still names "the dist README" as the stars credit's second home. Brief 06 leaves only §C and §E to the session, not §A.
- §C (:66-72) lists no shadows startup line.
- The plan's release gate says "nine startup lines plus the packs'", but export.sh expects 7 plus the packs (9 in all).

**Fix:** in the session's release-docs commit, name the Release notes as §A's second home, add the shadows line to §C, and correct the plan's count.
