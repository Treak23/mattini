## New findings

**N1 (P3).** The `star_image` comment (`sky_rig.gd`) says "a right ascension out of range was drawn at a wrong column". It was not.
- The code computes `% STAR_WIDTH` and then `posmod` (lines 184 and 188).
- Godot 4.6.3 printed `-1.0 col -12 posmod 4084` (the column of RA 359) and `370.0 col 113` (the column of RA 10).
- So the comment misstates the code (Hard Rule 2).

**Fix:** reword it. An out-of-range right ascension is refused as a malformed table, not as a placement error.

**N2 (P3).** The declination guard refuses exactly ±90 only. The run width `half = floor(0.5/cos dec)` (line 186) has no upper bound:
- at dec 89.9999999 it is 2.86e8 (about 5.7e8 dictionary writes per star), effectively the hang the comment says the guard prevents;
- at dec 89.99 it is 2864, more than half the row, so the run wraps and adds the star's light twice.

The shipped table tops out at Polaris (+89.26, half 38), so nothing shipped is affected.

**Fix:** `half = mini(half, STAR_WIDTH / 2)`, or a stated declination bound, pinned under a timeout.

**N3 (P3).** The notes tell players to run `sha256sum -c SHA256SUMS` "beside the unpacked archives". A player with one platform's archive gets this, exit 1:

```
b/g: FAILED open or read
WARNING: 1 listed file could not be read
```

With `--ignore-missing` the same check passes (exit 0).

**Fix:** write `sha256sum -c --ignore-missing SHA256SUMS` in the notes.

**N4 (P3).** Check 5 of `release_checks.sh` (lines 244-263) prints "exited by itself before the log held the startup lines" whenever the process died, even when `both=1`. The verdict is right; the message can be false.

**Fix:** branch on `both` as well and word the message for that case.
