## Findings

### S-01 (P2) nothing proves res://sky/stars.csv is in the exported packs
tools/export.sh step 4c walks only `assets/generated`; step 6 prints no stars line (the sky block prints none); export_presets.cfg include_filter lists `assets/generated/*` and three licence files but not `sky/*`; docs/RELEASE.md has no stars check. main.gd makes the table's presence the switch (`FileAccess.file_exists`), and the credit follows the image. If the export drops the table the build ships a starless night, without ESA's credit, and every gate stays green (brief 06 itself notes that an export without the keep file ships translations, not the table, so the failure mode is known). Whether the keep importer ships the file outside assets/generated is unverified here (the existing keep files are all covered by the include_filter).
Fix shape: in export.sh 4c (or the Linux start) require `sky/stars.csv` in mattini.pck, or add `sky/*` to the include_filter and check it; pin with a test_export test.

### S-02 (P3) the placeholder sun is a second home for config/shadows.json's sun
main.gd:121-122 (184.67, 50.1) says "from config/shadows.json"; test_m4_10_refusals.gd:73 pins the literal; no test or code ties either to the file (only test_m4_09_sky_config.py derives 184.67 from sky.json's convergence). A recomputed shadows.json leaves the placeholder stale with its comment still true-sounding.

### S-03 (P3) the type-guard and world-guard censuses stop at six readers
test_m3_r1_fix5_type_guards.gd READERS/BLOCKS and test_m3_r1_fix5_world_guard.gd do not include SkySite, the seventh manifest reader. SkySite has its own guards in test_m4_10_sky_site.gd and test_m4_08_fix_sky.gd (tested one wrong type of world_sha256 at the block, one at the manifest), so no wrong result found, but the "every reader" statement is no longer true and the next field added to the sky block gets no sweep.

### S-04 (P3) 0.3.1 wording left in the tree
test_main_scene_terrain.gd:10 still says the main scene builds "a fixed sun" (the test only checks the node exists, so it passes); docs/SPEC.md:831 and :851 describe one fixed sun and a procedural sky as the current look; main.gd's header (line 12-14) lists the blocks whose refusal opens the panel without the sky. CLAUDE.md's Layout omits config/sky.json, game/sky/stars.csv and tools/stars_table.py.

### S-05 (P3) star_image has no guard for |dec| >= 90
sky_rig.gd star_image: half = floor(0.5/cos(dec)) is 8e15 at dec exactly +-90 (a loop that never ends) and negative beyond; the shipped table's maximum is 89.2641 (half 38), so only a changed table triggers it. tools/stars_table.py (the generator) is run by no test; the table's content is pinned by GUT, the generator is not.

### S-06 (P3) the clock leaves SkyClock's validated range without saying so
SkyClock states its vectors cover 2020 to 2035 and "nothing here claims more", but day_later/day_earlier are unbounded and the label shows only the date; Zurich's offset rule is applied to every year. Nothing is wrong inside the range; outside it the sun's accuracy and the DST rule are unvalidated and the player is not told.

### S-07 (P3, unverified) the sky shader's up is scene +y while the rig contracts on the frame's up
sky_physical.gdshader uses `UP = vec3(0,1,0)`, `dir.y` and `.xz` for twilight; the rig's doc and test_main_scene_light's "turned world" case claim elevations are measured against the frame's up. The test proves the lights only. Unreachable with the owner's axes (SurfaceGrid refuses other axes), so a latent premise, not a result.

### S-08 (P3, unverified visual) linear filtering of the flow texture
The flow is filtered bilinearly after the 128-centred encoding: where neighbouring cells differ a lot in bearing (confluences, sharp bends) the interpolated vector shrinks, and blue (the mask) fades at the corridor's edge, so drift slows there. A look value of the technique; nothing fails.
