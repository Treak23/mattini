# RELEASE.md — what must be true before a build reaches the owner or anyone else

Walk it top to bottom before any version bump.

## A. Preconditions — every one, or the arc stays OPEN

- [ ] `git status --porcelain` is empty.
- [ ] Every brief in the arc reads `Status: DONE (<commit sha>)`.
- [ ] No production code in the arc was written by the design realm (DESIGN.md rule 5).
- [ ] No brief carries an unfinished-review note; a truncated round is a round that did
      not happen.
- [ ] No gate is a source census standing alone over code that runs at scene load,
      `_ready()`, autoload initialisation or pipeline start-up (BUILD.md 3b).
- [ ] Every gate's "does NOT prove:" line is filled in. Read them as a set: they are the
      honest list of what this release has not been shown to do, and the report-back
      names the visual ones for the owner to look at.
- [ ] **Attribution:** the credits show `© swisstopo` and any dataset-specific wording
      for every dataset in the build (CLAUDE.md Hard Rule 3), and the licence notices of
      the third-party code the build ships: Godot and its components, Terrain3D, and
      godot-cpp, which is compiled into Terrain3D's library (all MIT; its notice since
      M2-02, `game/credits/godot-cpp-LICENSE.txt`; 0.1.0 lacked it, D17).
- [ ] **No raw data or unmanaged binaries** entered git history in this arc, but the
      one real sample the owner allowed (SPEC §13 row 24), which `test_repo_hygiene.py`
      names with its SHA-256.

## B. The bump

- [ ] Version raised in `game/project.godot` (`application/config/version`) and shown
      in the game on the pause screen, the only place it shows (SPEC §11, §13 row 15).
- [ ] Full gate from clean, redirected to a log, exit status checked; never piped.

## C. Delivery — (b), the owner's choice (2026-09-24)

**Exported binaries on a `dist` shelf** (orphan branch, never merged, never deleted):
- [ ] The generated assets the build ships were regenerated by the pipeline from the
      pinned inputs (SPEC §Storage) in a fresh checkout, not copied from an unknown one.
- [ ] Every built output has its designed value: the village heights at 0.5 m `b6334c1f…`
      (SPEC §8); the six building chunks (`config/buildings.json`); from M3, the photo's
      pixels and JPEG (`config/photo.json`), the roof colours (`config/roofs.json`), the
      surfaces by their pixels only (`config/surfaces.json`: the PNG's bytes depend on zlib)
      and the six tree chunks (`config/trees.json`). `terrain`, `buildings`, `photo`,
      `roofs`, `surfaces` and `trees` compare before they write, and `manifest` refuses any
      other file (M2-01, M2-04, M3-04 to M3-07, M3-13), so their exit 0 in the fresh
      checkout is the check.
- [ ] Windows and Linux exports built with the pinned Godot version's export templates,
      each with its data packs beside the executable (`tools/export.sh` steps 4–4b:
      `mattini-terrain.pck`, `mattini-photo.pck`; from M3-08, SPEC §11).
- [ ] Every generated file ships once, byte for byte: `tools/export.sh` step 4c reads the
      directory of every pack in both folders and compares it with `game/assets/generated/`
      (a file in two packs or in none, other bytes, a `.part` or `.import` shipped, a file of
      10 MiB or more left in `mattini.pck` fail it).
- [ ] No file over 100 MiB (104'857'600 bytes; GitHub rejects it), the data packs included.
      If one is larger, stop: a further split is a design question (SPEC §11, §14).
- [ ] The Linux export starts: `tools/export.sh`'s step 6 runs
      `build/linux/mattini.x86_64 --headless --quit-after 300` and requires one line per
      data pack, then the terrain's startup line (columns, rows, spacing), the buildings'
      (their count) and, from M3-14, the photo's, the surfaces', the trees' and the roofs'
      lines, and no `ERROR` line (M2-02, M2-05, M3-08, M3-14).
- [ ] The build written to `windows/` and `linux/` (fixed names: the current version)
      and to `mattini-<version>/windows/` and `…/linux/`; the previous version's named
      folder stays as the rollback; keep the last three named folders (older ones stay in
      the branch's history). Never rename files per version: an executable finds its
      `.pck` by its own name, its data packs by the pattern `mattini-*.pck` beside it, and
      Terrain3D's library has a fixed one (M1 close, D15).
- [ ] `README.md` names the current version and its source sha, says how to download,
      start and roll back, lists every file's SHA-256 (the data packs included) and says to
      keep the five files of a folder together: the game, `mattini.pck`, the data packs and
      Terrain3D's library; without its terrain pack the game says "mattini cannot show the
      terrain", and the fix is to download the folder again (from M3-08; the exported
      game's error panel says the same from M3-14);
      `.gitattributes` holds `* binary`, with the README as text.
- [ ] The dist commit carries the version, the `main` sha it was built from, and the
      gate's exit line.
- [ ] `git push origin HEAD:dist`, plain, never forced.

## D. The record

- [ ] `docs/releases/v<version>.md` committed BEFORE the chat message: version, source sha,
      the FB ids it closes, what the review found, what this release does NOT prove (the
      visual checks for the owner), and what to do if it will not start.
- [ ] Report-back in chat as a copy of the record; owner-reported items separate from
      review-found ones; plain text.
- [ ] The board updated (shipped line, OPEN list, DEFERRED list); the close's narrative
      moved to `docs/history/`.
- [ ] No Routine left running.

## E. When the owner reports a broken build

Point at the rollback immediately, in the first reply, before any diagnosis: the
previous version's named folder on `dist` (before the second release there is none). Then
diagnose.
