## Goal

`tools/export.sh` refuses, before it downloads, installs or exports anything, a release whose
data packs are not exactly the ones the game expects: it reads `DataPacks.EXPECTED_PACKS` from
`game/scripts/data_packs.gd` (step 2b) and compares it, in order, with the packs its own
`PACKED_FOLDERS` makes. After step 4b it refuses, before the Linux build is started, a release
whose packs written are not exactly that list. Its header comment describes both. The
stand-ins its tests run on (`pipeline/tests/fake_tools.py`) gain `data_packs.gd`, both packed
folders and the pack tool, so the export's tests run the new checks; seven pinned test cases
prove them, three tests of your own cover the branches the pins do not reach. Nothing changes
in the game.

Not this brief: DataPacks, `ReleaseBuild` and the readers' "download the release folder again"
hint (v0.3.1-03, before this one); DataPacks' errors on the error panel and the pause cap
(v0.3.1-05); the photo's shadow lift and its `render_lift` render script (M4-06's other half,
next release); any other export step.

3. **The one line the script reads** (M4-08 decision 4: EXPECTED_PACKS is "on one line
   (tools/export.sh reads it with a regular expression)"). Step 2b reads
   `game/scripts/data_packs.gd` as text, with a CR at a line's end removed first (the gate's
   rule for every scan), and takes the lines that match this extended regular expression,
   exactly:
   ```
   ^const EXPECTED_PACKS := \["[^" ]+"(, "[^" ]+")*\]$
   ```
   Exactly one line must match; none, or more than one, is refused (decision 4's second
   message). The pack names are the quoted strings of that line, in the order written. A name
   cannot hold a blank or a quote (the expression refuses one), so the lists can be compared as
   their names joined by one blank. A constant written over several lines, typed
   (`const EXPECTED_PACKS: Array[String] = …`), or with a comment after it is refused, by
   design, not read: v0.3.1-03 wrote the line exactly as above. Use only bash (its builtins
   such as `mapfile`, `printf` and parameter expansion), `sed`, `grep` (`-E`, `-o`, `-c` as you
   need them) and `tr` for this; no Python, no `uv`, no Godot (the step runs before the
   templates exist).
4. **The messages, word for word.** A refusal goes through the script's `fail`, which prints
   `export: ` before it, on stderr (the tests read stdout and stderr together). `<E>` is the
   names read in decision 3, in their order, joined by one blank; `<W>` is
   `mattini-<folder>.pck` for each folder of `PACKED_FOLDERS`, in its order, joined by one
   blank; `<P>` is the packs step 4b wrote (`PACKS_WRITTEN`), in order, joined by one blank, or
   `none` when it wrote none.
