## Goal

`python -m mattini surfaces` also writes, beside the class PNG, a flow grid: for every 2 m cell
of the area's box, one byte holding the downstream bearing of the nearest drawn stream
(swissTLM3D draws its watercourse lines downstream), in 1.5° steps, 0 where no stream lies within
12 m. The step compares the flow's pixels and its PNG's bytes with design's values in
`config/surfaces.json` before it writes anything, writes `surfaces/<area>-flow.png` and its keep
file, and describes them in a new `flow` object of the surfaces description and so of
`manifest.json`; `manifest` refuses a built flow that is not design's. The game's `SurfaceGrid`
accepts the new key (it reads nothing of it until v0.4.0-02). Every pinned test passes, every
other test still passes, and the real village's flow is design's value
(`c05a7535…`, measured two ways by the pin author).

Production code is `main` at `4d4cc63`. The pin author rehearsed this brief in a clone of it
(2026-10-27): the pins red on `main`'s code, green on a throwaway implementation, the full gate,

   def flow_code(dx: int, dy: int) -> int:
       if dx == 0 and dy == 0:
           return 0
       bearing = math.degrees(math.atan2(dx, dy)) % 360.0
       return 1 + round(bearing / FLOW_STEP_DEG) % FLOW_CODES

4. **The painting** (the session's decision 4): segments whose code is 0 are dropped (never painted). Then in
   passes of radius `FLOW_RADIUS_M`, `FLOW_RADIUS_M − 1`, …, 1 m (in mm: r × 1000), each pass
   paints every remaining segment's stadium (the texels whose centre lies within r of the segment,
   ties included) with its code, in segment order, a later paint overwriting an earlier one, and a
   pass overwriting the earlier passes where it paints. So a cell takes the code of a nearest
   segment to within 1 m (ties to the later), and keeps 0 where no segment lies within
   `FLOW_RADIUS_M`. **The tie to the later segment is a known limit** (the session's ruling,
   2026-10-27): measured on the village against the strictly nearest segment, 17'504 of 54'562
   painted cells take another segment's code (almost all a neighbouring segment of the same line
   within 1 m), 344 differ by more than 45° and 14 by more than 90°; of the 14'632 flow cells
   holding water, 25 differ by more than 45° and 3 by more than 90°, near confluences. The rule
   stands; the confluence cells are recorded, not revisited in this release. The painter below
   (`_stadium_cuts` and `_paint_over`) is the pin author's (accepted by the session 2026-10-27).
   Use the class grid's exact stadium arithmetic: refactor `_stadium_spans` into
   `_stadium_cuts`, which also returns each span's segment index (in `_stadium_spans`' loop,
   `index_parts.append(s[reached].astype(np.int64))` beside the other three; `_stadium_spans`
   becomes `return _stadium_cuts(frame, ax, ay, bx, by, rr)[1:]`, so `class_grid` is unchanged).
   Within a pass, "the later paint wins" is "the highest segment index covering the texel wins";
   the rehearsal's painter, exact and integer only:
   ```python
   def _paint_over(grid, frame, codes, index, rows, starts, ends) -> None:
       if not len(rows):
           return
       lengths = (ends - starts).astype(np.int64)
       cells = np.repeat(rows.astype(np.int64) * frame.columns + starts, lengths) + (
           np.arange(int(lengths.sum())) - np.repeat(np.cumsum(lengths) - lengths, lengths)
       )
       last = np.full(grid.size, -1, dtype=np.int64)
       np.maximum.at(last, cells, np.repeat(index, lengths))
       covered = np.flatnonzero(last >= 0)
       grid.ravel()[covered] = codes[last[covered]]
   ```
   called once per pass with that pass's `_stadium_cuts` of the non-zero segments and their codes
   (`codes[i]` for segment i). Never use a fancy-index assignment with repeated indices to mean
   "the last wins": numpy does not promise an order.
