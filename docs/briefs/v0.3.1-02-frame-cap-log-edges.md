## Goal

The game runs at most 60 frames a second, so the owner's 300 Hz laptop no longer renders flat
out (FB-007: 94 % GPU on average in 0.3.0, also while paused). A release build writes each log
line to stdout and `godot.log` when it is printed, not at exit, so a crash keeps them (FB-006).
3D is drawn with 4× MSAA against the jagged edges of trees and buildings (FB-004). All three
are project settings in `game/project.godot`, read back by one pinned test as Godot loaded the
project (`ProjectSettings`), the cap and MSAA also as the running engine took them
(`Engine.max_fps`, the root viewport's `msaa_3d`); the flush has no engine-side value to read.
The gate's render step is measured before and after the change, and software images of a
crown's edge, before and after, are committed as evidence.

Not this brief: the 15 fps cap while the pause screen is open (v0.3.1-05); DataPacks and the
readers' "download the release folder again" hint (v0.3.1-03); `tools/export.sh`'s pack checks
(v0.3.1-04); exposure (stays 0.54, the owner's answer 1 in
`docs/history/blocked/2026-10-25-1.md`); anisotropic filtering or any other rendering setting.
