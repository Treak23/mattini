2. **A Release only from `main`** (session; owner N2): a new step **"the sha is on main"**
   after "the checkout is the sha" and before Godot (so before any download; the pins check
   that order, not its place against "free disk", which downloads nothing):
   `git fetch --no-tags origin "+refs/heads/main:refs/remotes/origin/main"` (main alone, never
   all branches: `dist` holds 167 MB of packs; no `--unshallow`, no `fetch-depth` on the
   checkout), then `git merge-base --is-ancestor "$RELEASE_SHA" refs/remotes/origin/main`; on any
   non-zero exit it prints `<sha> is not on main (main is <main's sha>) …` and exits 1. Pinned by
   running the step in a shallow checkout of the sha (as `actions/checkout` leaves it) from a
   scratch origin with `main`, `dist` and another branch: main's tip and an older commit of main
   pass; a commit of another branch is refused, naming the sha and main; no branch but `main` is
   fetched (the other branches' commits stay absent). The checkout keeps `persist-credentials:
   false`: the fetch is unauthenticated, which works while the repository is public (it is,
   2026-11-02; a private repository fails the step, closed: PINSPEC open question 3).
3. **Check 5's words** (session; N4): in `check_live_log`, when the game exited by itself (the
   verdict stays FAIL), the line says which: after it, the output and godot.log are read once
   more; all startup lines in both: `FAIL the process exited by itself after <s> s (no
   --quit-after was given); the output and godot.log held all <n> startup lines`; otherwise
   `FAIL the process exited by itself after <s> s (no --quit-after was given), before the output
   and godot.log held the startup lines`. The pins require "exited by itself", "held all <n>
   startup lines" and neither "before" nor "lacked" in the first case; "exited by itself", "before"
   or "lacked" and not "held all" in the second (your words may differ around those).
4. **§C's manifest line** (session; S-02): docs/RELEASE.md §C's one command becomes
   `size="$(wc -c < game/assets/generated/manifest.json)"; echo "manifest.json: $size bytes"; if
   [ "$size" -eq 326124 ]; then echo "f68275a1…  game/assets/generated/manifest.json" | sha256sum
   -c -; else echo "the size check failed: $size bytes, the plan names 326124"; false; fi` (the
   full SHA-256 as today; 0.5.0's pair stays: the session writes 0.6.0's at the integration
   rehearsal, design §5). The pin reads the one inline code span of §C holding `wc -c <
   game/assets/generated/manifest.json` and `sha256sum -c`, requires exactly one 64-hex and one
   size in it, replaces them with a scratch manifest's or others, and runs it with bash: the pair

   printing the size found and the word "size"; another SHA-256 exits non-zero printing the size
   and `FAILED`. Its limit (a doc): it cannot prove the numbers are the release's, nor that the
   session pastes the line.
