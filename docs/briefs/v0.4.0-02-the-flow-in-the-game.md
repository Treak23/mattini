## Goal

`SurfaceGrid` (`game/scripts/terrain/surface_grid.gd`) reads the surfaces block's `flow` object as
v0.4.0-01 writes it, checks it as it checks the classes (the block's fields; the flow PNG's
SHA-256 before decoding; L8 of exactly the block's size; its decoded bytes' SHA-256; no code above
240; every file message through `ReleaseBuild.file_hint`), and makes the flow texture: RGB8, one
texel per 2 m cell, each code's downstream direction turned into the world's local (x, z) through
`WorldConfig`. `flow_at(x, z)` gives the decoded direction at a local point. The complete test
world carries the flow, so every scene test and the render step read it. Nothing draws it yet
(v0.4.0-03). Every pinned test passes, every other test still passes.

Production code is `main` once v0.4.0-01 has landed. The pin author rehearsed this brief in the
clone v0.4.0-01's rehearsal left (2026-10-27: `main` at `4d4cc63` with v0.4.0-01's pins and
throwaway): the pins red on v0.4.0-01's reader, green on a throwaway implementation, the full gate,
all fifteen mutation rows both ways, and the real village's flow read by a probe. Every number
marked "rehearsal" was measured there (the pin author's record,
`docs/briefs/sketches/v0.4.0/v0.4.0-02-PINSPEC.md`, committed by the session; you do not need

4. **The colours** (the session's decision 2: through `WorldConfig`, 64-bit floats, the (x, z)
   part normalised; Hard Rule 4; brain.md H5). The exact arithmetic below, the normalisation in
   64-bit floats that decides the eight tie codes, the TIES pin and mutation row 15 are the pin
   author's; accepted as the session's ruling, 2026-10-27. A table of 241 colours,
   made once per read through the WorldConfig given; the CODE lines exactly as here (comments may
   be worded otherwise if they stay true):
   ```gdscript
   ## The flow texture's R, G and B for each code 0 to FLOW_CODES (three bytes per code): code 0
   ## (128, 128, 0); code k the local (x, z) direction of the LV95 grid bearing
   ## b = (k − 1) · FLOW_STEP_DEG, east sin b and north cos b from the world's origin through
   ## [param world] (Hard Rule 4), normalised in 64-bit floats; R = round(128 + 127 x),
   ## G = round(128 + 127 z), B = 255.
   static func _flow_colours(world: WorldConfig) -> PackedByteArray:
   	var colours := PackedByteArray([128, 128, 0])
   	for k in range(1, FLOW_CODES + 1):
   		var bearing := deg_to_rad((k - 1) * FLOW_STEP_DEG)
   		var local := world.to_local(
   			world.origin_e + sin(bearing), world.origin_n + cos(bearing), world.height_offset
   		)
   		var x: float = local.x
   		var z: float = local.z
   		var length := sqrt(x * x + z * z)
   		colours.append(roundi(128.0 + 127.0 * x / length))
   		colours.append(roundi(128.0 + 127.0 * z / length))
   		colours.append(255)
   	return colours
   ```
   - Why through `to_local` from the origin: the axis mapping has one home (`config/world.json`,
     read by `WorldConfig`); the existing guard `_check_world` refuses any mapping but x = +e,
     z = −n, and nothing here assumes it beyond that guard. The 64-bit subtraction happens inside
     `to_local`; only the small local vector is narrowed to `Vector3` (float32).
   - **Why the normalisation is in 64-bit floats (`var x: float`), never
     `Vector2(...).normalized()`:** at eight codes (21, 41, 81, 101, 141, 161, 201, 221: the
     bearings 30°, 60°, 120°, 150°, 210°, 240°, 300°, 330°, where sin or cos is ±1/2) the exact R or
     G is a rounding tie (64.5 or 191.5). With this arithmetic the other component's float32
     narrowing puts the tied one 8.5e-7 beyond the tie, and the bytes are 64 or 192 (128 ± 64: a
     direction and its reverse decode to exact opposites). A float32 normalisation lands exactly on
     the tie and gives 65 at codes 41, 141, 201 and 221: the pinned tests fail on it (mutation row
     15). At the other 232 codes every byte is at least 0.009 from a rounding boundary (rehearsal,
     exact arithmetic), so no float detail moves them.
   - Rehearsal, two ways: the table emulated in Python (IEEE doubles, numpy's float32 narrowing,
     Godot's half-away-from-zero `roundi`) and printed by Godot through three WorldConfigs (the
     surfaces fixture's origin 2'700'000 / 1'200'000, the village's 2'623'000 / 1'096'000, the
     terrain fixture's 2'600'000 / 1'200'000): identical, SHA-256 of the 723 bytes `ef1471da…`.
5. **The flow texture** (the session's decision 2): for every cell i (row-major, rows from the
   north, as the PNG) the three bytes `colours[3 * code]`, `+ 1`, `+ 2`, into a `PackedByteArray`
   of `3 · columns · rows`; `Image.create_from_data(flow_columns, flow_rows, false,
   Image.FORMAT_RGB8, rgb)` (no mipmaps); `flow_texture = ImageTexture.create_from_image(image)`;
   the bytes kept as `_flow` for `flow_at`. The shader (v0.4.0-03) reads `(rg · 255 − 128) / 127 ·
   b` with a linear filter: code 0's B = 0 means no drift, and so does an unset sampler once
   v0.4.0-03 declares it `hint_default_black` (the session's ruling, 2026-10-27: without a hint,
   Godot 4.6.3 reads an unset sampler as white, a diagonal drift). The filter and the default are
   the shader's sampler hints, not this texture's: nothing to set here.
6. **`flow_at`** (the session's decision 3), exactly:
   ```gdscript
   ## The downstream direction, local (x, z), of the flow cell holding the local point
   ## ([param x], [param z]), decoded from the flow texture's bytes as a shader reads them:
   ## ((R − 128) / 127, (G − 128) / 127) · B / 255. Column floor((x − x0) / flow_cell_m), row
   ## floor((z − z0) / flow_cell_m), half-open as class_at; outside the grid and on a cell with no
   ## stream (code 0) the zero vector.
   func flow_at(x: float, z: float) -> Vector2:
   	var column := floori((x - x0) / flow_cell_m)
   	var row := floori((z - z0) / flow_cell_m)
   	if column < 0 or row < 0 or column >= flow_columns or row >= flow_rows:
   		return Vector2.ZERO
   	var at := 3 * (row * flow_columns + column)
   	var mask := _flow[at + 2] / 255.0
   	return Vector2((_flow[at] - 128) / 127.0, (_flow[at + 1] - 128) / 127.0) * mask
   ```
   placed after `class_at`. For tests and checks; the shader reads the texture.
