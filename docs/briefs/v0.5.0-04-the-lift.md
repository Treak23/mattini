## Goal

The terrain shader lifts the aerial photo where it lay in shadow when it was flown, so the 2023
photo's baked shadows no longer darken the ground a second time under the game's own sun (SPEC §13
rows 41 and 47). `TerrainLoader.create` takes the capture-shadow mask (`CaptureShadowGrid`,
v0.5.0-03) as an optional fifth argument and hands its texture and rectangle to the photo shader;
without a mask the shader gets one texel of 0 and lifts nothing. The shader multiplies the photo's
colour, in linear light, by 1 + (`shadow_lift` − 1) · m, m the mask filtered at the world point (0
outside its rectangle), clipped at 1, as the first rule on the photo. The gate's render step gains
a third script, `render_lift.gd`, which measures where the lift lands and how strong it is. The
main scene does not hand the mask yet (a later batch, M4-10), so the owner sees nothing new, and
the three RENDER lines of today stay digit for digit.

Production code is `main` at the head you start from (rehearsed on v0.5.0-03's rehearsal: `main`
at `d522abf` with v0.5.0-03's pins and throwaway reader). The pin author rehearsed this brief in a
clone of it (2026-10-30): the pins red in two steps, green on a throwaway, the full gate with the

2. **The lift** (M4-06 decision 3; m4-design §8; SPEC §13 rows 41 and 47), in
   `terrain_photo.gdshader`:
   ```glsl
   group_uniforms capture_shadow;
   // (your comment: what the mask is, data, where it lies, the feather, its mipmaps, unset = no lift)
   uniform sampler2D capture_shadow : hint_default_black, filter_linear_mipmap_anisotropic, repeat_disable;
   uniform vec4 capture_shadow_rect = vec4(0.0, 0.0, 1.0, 1.0);
   uniform float shadow_lift = 3.0;
   ...
   	vec2 puv = (v_vertex.xz - photo_rect.xy) / photo_rect.zw;
   	vec3 albedo = texture(photo, puv).rgb;
   	vec2 muv = (v_vertex.xz - capture_shadow_rect.xy) / capture_shadow_rect.zw;
   	float m = texture(capture_shadow, muv).r;
   	if (any(lessThan(muv, vec2(0.0))) || any(greaterThan(muv, vec2(1.0)))) {
   		m = 0.0;
   	}
   	albedo = min(albedo * (1.0 + (shadow_lift - 1.0) * m), vec3(1.0));
   	if (any(lessThan(puv, vec2(0.0))) || any(greaterThan(puv, vec2(1.0)))) {
   		albedo = outside_albedo;
   	}
   ```
   - **Where:** the `capture_shadow` group goes right after the `photo` group (after
     `outside_albedo`, before `group_uniforms surfaces;`): the pinned placement census
     (`test_m3_09_photo_shader.gd`) lists `capture_shadow_rect`'s declaration between `photo_rect`'s
     and `surfaces_rect`'s (pin author; accepted by the session 2026-10-30). The fragment lines go
     between the photo's sample and the neutral colour outside it, exactly as above.
   - **The sampler reads the mipmaps** (the session's decision; amends M4-06 decision 3, which said
     `filter_linear`): `filter_linear_mipmap_anisotropic`, the photo's own filter. v0.5.0-03 gave the
     mask a full mip chain so the 0.5 m binary mask does not alias in the distance; a sampler
     without a mipmap filter would never read it. Close up (magnified) it is the same bilinear
     filter between the 0.5 m texel centres, the feather M4-03's inset keeps inside the shadow
     (rehearsal: `RENDER lift` prints the same correlation 1.0000 with `filter_linear`, "nearest"
     0.9827 against 0.9829). The distant evidence: the integration rehearsal's software Forward+
     render (2026-10-30): with mipmaps the lift's speckle beyond 350 m 23 % (start view) and 28 %
     (far view) lower, its frame-to-frame flicker 6 to 7.5 % lower; no visible crawl either way. The lift is linear in m, so a mip level's mean m lifts a pixel by the
     mean of its texels' lifts (before the clip): say so in the comment.
   - **The mask is data:** no `source_color`; `hint_default_black`, so an unset sampler lifts
     nothing (an unset sampler without a hint reads white, brain.md H29, which would lift the
     whole photo); `repeat_disable` clamps to the edge texel, hence the explicit 0 outside the
     rectangle.
   - **Linear light:** `photo` is a `source_color` sampler, so under Forward+ `albedo` is linear
     here and the lift multiplies linear colour, as the prototype the owner judged did
     (`docs/briefs/sketches/M4-soften/README.md`). Nothing converts it around the lift.
   - **Order:** the lift is the first rule on the photo: before the neutral colour outside the
     photo (never lifted) and before rock, road, path and water.
   - **Clipped at 1** per channel, as the prototype (M4-soften: "2 % clipped inside the mask
     (village)"). `shadow_lift` 3.0 is the owner's G = 3 (SPEC §13 row 47).
   - **The header comment** at the top of the shader says what the lift does (Hard Rule 2: a
     comment never claims what the code does not do), in the shader's own words.
   - **Decided but not pinned** (the release's checkers, 2026-10-30; for the batch gate's mutation
     prover and `test_v0_5_0_04_gaps.gd`): the header comment's words about the lift (no test
     reads them), and the no-mask rectangle `capture_shadow_rect` (0, 0, 1, 1) of decision 1 (the
     pins read the no-mask texel, never that rectangle).
