## Goal

`python -m mattini sky` writes the sun's place for the configured area, `sky/<area>.json`: exactly
`config/sky.json`'s latitude, longitude and true-to-grid angle with the area and the world
config's SHA-256, after checking the config, its world and its area. The manifest gains one key,
`sky` (ten keys at the top): that description, checked world, then area, then block, or null
until the step has run in the folder. The seven M2/M3 fixture manifests gain one line, `"sky":
null`. And any command that meets a file-system error (an unusable `--out`, a folder where a file
belongs) ends in one `mattini: error:` line naming the path, never a traceback (I-03). Nothing in
the game changes (v0.4.0-08 reads the block).

Production code is `main` after v0.4.0-06. The pin author rehearsed this brief in a clone of the
session's `main` with v0.4.0-01 to -06's pins and throwaway implementations merged in
(2026-10-27): the pins red on that code, green on a throwaway implementation, the full gate, all
sixteen mutation rows both ways. Every number marked "rehearsal" was measured there.
The pin author's record is `docs/briefs/sketches/v0.4.0/v0.4.0-07-PINSPEC.md`, committed by the
session; you do not need it.

1. **The command** (M4-09 decision 1, the sky only; the session's decision 1).
   `python -m mattini sky` takes `--out` only (default `game/assets/generated`, the help text "output
   directory (default: game/assets/generated)" as the other steps'); it has no `--raw` (it reads
   no download: `sky --raw x` is argparse's usage error, exit 2). It does, through the modules
   (the tests replace `sky.build_sky` and `sky.load_sky_config` on the module):
   ```python
   sky.build_sky(load_world(), sky.load_sky_config(), out_dir, progress=progress)
   return write_manifest(out_dir)
   ```
   then prints the manifest's path on stdout, exactly as `_build_step` does (progress on stderr;
   the rehearsal printed one line, `wrote <path of sky/village.json>`; not pinned).
   - `from mattini import …, sky, …` in `__main__.py`; its sub-parser is added after the four M3
     steps' loop and before `manifest`, so the help lists, in pipeline order: `lock, download,
     terrain, buildings, photo, roofs, surfaces, trees, sky, manifest`.
   - The dispatch sits inside `main()`'s existing `try`, so a Ctrl-C is M3-03's one handler (one
     line naming `python -m mattini sky`, exit 130) and a `sky.SkyError` joins the `except`
     tuple: one `mattini: error: …` line, exit 1.
   - The module docstring of `__main__.py` says what `sky` does and the I-03 rule (decision 8).
2. **`pipeline/mattini/sky.py`** (new; M4-09 decision 2, quoted; m4-design §4): "The sky is a
   step. `config/sky.json` is design data with `computed_for` {world_sha256}, like every
   expected value; the block follows M3-13's rule for every block: null until its step has run
   in the folder." It holds exactly these public names (the tests import them):
   - `class SkyError(ValueError)`.
   - `SKY_CONFIG_PATH` = `REPO / "config" / "sky.json"`.
   - `load_sky_config(path=SKY_CONFIG_PATH) -> dict`: reads the file (an OSError, bad UTF-8 or
     bad JSON is a SkyError naming the path), then `check_sky_config(data, path)`.
   - `check_sky_config(data, where) -> None`: refuses, as a SkyError whose message names `where`
     (the rehearsal's starts with `f"{where}: "`), anything but `{"schema": 1, "areas": {<exactly one area>: {"computed_for":
     {"world_sha256": <64 lower-case hex digits>}, "latitude_deg", "longitude_deg",
     "true_to_grid_deg"}}}`: the top level exactly `schema` and `areas`; `schema` the int 1; one
     area; its keys exactly those four; `computed_for` exactly `{"world_sha256"}`, lower-case hex;
     the three values each `type(v) is float` (an int such as 46 is refused, a string too),
     finite, |latitude| ≤ 90, |longitude| ≤ 180, |true_to_grid| ≤ 10.
   - `build_sky(world, sky_config, out_dir, *, progress=None) -> dict`. The checks, in order:
     (1) `check_sky_config(sky_config, "config/sky.json")`; (2) the world: `world_sha256 =
     sha256(read_config_bytes(world.path))`, then `terrain.world_refusal("config/sky.json",
     computed_for, world_sha256)`; a difference is a SkyError (its words say "design recomputes"
     and name config/sky.json and config/world.json, never `python -m mattini sky`: rerunning
     cannot help); (3) the area: the config's one area (`terrain.configured_area(sky_config)`)
     must be in `world.areas`, or a SkyError naming the area (as `repr`, e.g. `'elsewhere'`) and
     `config/sky.json`, naming no command and not saying "design recomputes" (the pin author's
     wording, so the pins can tell world-first from area-first; accepted, the session's ruling,
     2026-10-27). Only then is
     anything written: `<out_dir>/sky/<area>.json` through a `.part` rename (write
     `<area>.json.part`, then `os.replace(part, path)`, called as `os.replace` on the `os` module:
     a test patches it), the text `json.dumps(block, indent=2, sort_keys=True,
     ensure_ascii=False) + "\n"` in UTF-8, where the block is exactly
     `{"area", "latitude_deg", "longitude_deg", "true_to_grid_deg", "world_sha256"}`: the config's
     three values verbatim (same floats) and the world's SHA-256. It returns the block. A refusal
     writes nothing (not even the folder).
   - `built_sky_block(out_dir, sky_config, world, world_sha256) -> dict | None`: `None` when
     `<out_dir>/sky/<area>.json` does not exist (the area is the config's); else the same world
     and area checks as `build_sky`, in the same order, against the `world_sha256` given; then the
     description must be exactly the block `build_sky` would write: the same key set, equal
     values, and each value of the same JSON type (`type(found[k]) is type(expected[k])`: an int
     where the config writes a float is refused; the same-type rule is the pin author's, accepted
     by the session 2026-10-27). Anything else, an unreadable file or bad JSON
     included, is a SkyError naming `python -m mattini sky`. It returns the description.
   - The module docstring says what the step is, the check order, and its "Does NOT prove" (that
     the values are the place's: `test_m4_09_sky_config.py` recomputes them; that the game turns
     azimuths with them). Pipeline code never names an area (`test_download_area.py` fails on
     "village" in `pipeline/mattini/`: say "the configured area").
