1. **The red is a collection error.** Every pinned file imports `mattini.shadows`, so the red run
   is four `ModuleNotFoundError`s, not failures by the harm's name test by test. M4-03's own
   rehearsal accepted the same and the module's absence is the harm (no step exists).
   Recommendation: accept, as the brief writes; the 19 mutation rows show each pin fails by name
   on a wrong step.
2. **Decision 12, the free test file** (`pipeline/tests/test_v0_5_0_01_gaps.py`, lesson 51) is a
   change to M4-03's Scope. Recommendation: keep, optional for the builder, for the prover's
   round 2 only.
3. **Nothing pins the inputs check of `built_shadows_block`** separately from the build (the
   pinned damaged-build cases are the PNG, the import, the description and a missing PNG). The
   manifest's check order in v0.5.0-02 pins it through `python -m mattini manifest` (M4-09
   decision 4). Recommendation: leave to v0.5.0-02 and the prover; no new pin here.
4. **The flight's 11.6° of azimuth against the mean sun** (the shadows scout): a 10 m building's
   shadow tip moves about 0.85 m, more than the 0.5 m inset. It is a look question for the owner
   at the lift's batch, not this step's; the brief's real-run box names it in its "does NOT
   prove". Recommendation: no change to the rule (row 41's design, row 47's owner judgment).
5. **The brief's real-run command** is a one-line `python -c` because the command line comes in
   v0.5.0-02. Recommendation: accept; the batch gate's verifier runs the same line.
6. **The faster march** stays an optional invitation (the triage's risk: drift). The pins' oracle
   and the step's own expected-value check bound any faster march to the same bits.
