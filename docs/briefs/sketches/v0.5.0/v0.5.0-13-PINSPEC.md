   unfinished, do not ship it` to the refusal. The pin author made it a line of its own, last,
   because step 4's and 6's refusals end with Godot's own lines (`ERROR: …`), where an appended
   clause would read as Godot's. Recommendation: keep.
2. **16 survivors** (decision 6): 4c's other checks (R12, R13, R16 to R20), the unpacked limit
   (R21), the started build's exit status (R22) and the `SCRIPT ERROR` scan (R23), the pack tool's

   to hand (a started build that crashes after its lines, a GDScript error in the build) and each
   needs only a stand-in start that exits 3 or prints `SCRIPT ERROR`. Recommendation: a next-release
   residue item "export.sh: the 16 survivors of v0.5.0-13's table", R22 and R23 first.
3. **The stand-in's damage seams** (`leave_out`, `change`, `export_output`) are test infrastructure
   in a pinned file; they model an export filter that misses a file, a file changed between the
   export and the check, and Godot printing an error. Recommendation: keep; they also serve the
   survivors' tests.

   `build/release/` (its default), and step 5 checks every file under `build/`; an archive over 100

   `export.sh` run in the same tree at step 5. The workflow runs the export once, before the pack,
   so the release is not affected. Not measured with real archives. Recommendation: a one-line note
   in `docs/RELEASE.md` §C or a next-release item; not this batch's Scope.

   behaviour (lesson 5); the behaviour was measured once by the pin author (the table above). It
   fails when pack.gd's words change, which is when the stand-in goes stale.
