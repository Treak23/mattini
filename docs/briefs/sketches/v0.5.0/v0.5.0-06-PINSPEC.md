## Open questions for the session

1. **Two inputs more than the task named** (`manifest_bytes`, `manifest_sha256`). The pair changes
   with every release that changes a generated file and is measured after the batches (this
   release's shadows block changes it); a committed file would need a value nobody has when this
   batch lands (lesson 31), and RELEASE.md §C already says "the release's plan names its pair".
   Recommendation: keep them as inputs; the session passes the plan's pair when it triggers.
   Alternative: a committed `tools/release_manifest.txt` the session writes before triggering.
2. **PyYAML is a transitive dependency** (through gdtoolkit, the dev group). If gdtoolkit drops it,
   the workflow test fails at its import (loudly, not skipped). Recommendation: accept it for 0.5.0;
   declaring `pyyaml` in the dev group is a new direct dependency for the session to confirm
   (CLAUDE.md), not a builder's choice.
3. **The runner may refuse the surfaces PNG** (brain.md H27: its bytes depend on the zlib build).
   Pillow wheels bundle their own zlib; whether the runner's run of `surfaces` (and `photo`'s
   JPEG) gives design's bytes is unmeasured until the first dry run. If it does not, the step
   refuses (by design) and the fallback is the triage's: deliver that release by the container
   route, and decide the zlib question at the next release.
4. **The archive shape** (pin author): one folder per archive, `mattini-<v>-<platform>/`, five files,
   no folder entry; SHA256SUMS lists the archives and the ten files by their path inside. The
   triage did not fix this. Recommendation: keep it (the player unpacks one folder that holds what
   must stay together; the inner lines let a player check a file after unpacking).
5. **uv on the runner** comes from `pipx install uv==0.11.32` (pipx is on GitHub's Ubuntu images);
   the hook keeps using the container's own uv, so `UV_VERSION` binds the runner only. The runner's
   Python 3.13 comes through uv (python-build-standalone, from github.com, which a runner reaches).
   Unmeasured until the dry run.
6. **Two readers of the pack format**: release_checks.sh carries a short reader of format 3 (the
   directory only) beside export.sh step 4c's, which the brief forbids changing. Recommendation:
   accept for 0.5.0; a shared reader is a later tidy-up when export.sh is next opened.
7. **The first live proof is the session's** (the brief says so): land the batch on `main`, prove
   `actions_run_trigger` on `janitor.yml` first (the critic's precondition: the MCP identity has
   never dispatched a workflow), then a dry run of this workflow on a sha with the plan's pair; the
   batch's DONE does not wait for it, the release does.
8. **`timeout-minutes: 180` and the free-disk list** are estimates from repository figures (inputs
   about 6-7 GB, export templates 1.26 GB); the dry run measures them.
