## Open questions for the session

1. **The skirt faces out of the cut (design §3, pinned literally).** A camera in the village (in the
   cut) sees the skirt's back face, which `CULL_BACK` drops: where the far edge lies above the near
   terrain's edge, the crack seen from the village stays open; the skirt hides it only seen from
   outside (probe.md 5: "the skirt helps from outside only"). Options: (A, taken, design's words) the
   front out; (B) the front into the cut; (C) a double-sided skirt (its own material with
   `CULL_DISABLED`, which breaks decision 9's "one material"). A or B is one test line (the sign of
   `front.dot(outward)`) and the normals' sign; easy to undo either way.
2. **The fixture's colour is this brief's placeholder.** v0.6.0-06 makes the far colour step and may
   want the fixture's `fixture_colour.jpg` to be its step's output from a synthetic SWISSIMAGE input.
   Options: (A, taken) 08 pins a designed JPEG (15 × 18 at 1000 m, `filled_fraction` 0.2); 06 either
   produces exactly these bytes or re-pins 08's JPEG, manifest, `test_v060_08_surroundings_fixture.py`
   and the two corner values in `test_v060_08_surroundings_colour.gd` (the rest of the GUT tests read
   whatever JPEG the block names); (B) 06 first, 08 after it.
3. **The command names.** The colour's file hints name `python -m mattini farcolour` and the null
   block names `download regio`, `download farphoto`, `surroundings` and `farcolour` (design §2
   names the step `farcolour` and the commands `lock farphoto` / `download farphoto`). If v0.6.0-07
   folds the colour into `python -m mattini surroundings`, one constant and one test line change.
4. **`colour_source` carries no entry digest.** The heights' `source` has `entry_sha256`; I left the
   colour's out (the fixture's lock has no `swissimage_far` entry, so any value would be invented).
   Option B: add `entries_sha256` (design §5's `lock.entries_sha256`) in v0.6.0-07, re-pinning the
   key sets here (one constant, the fixture block, two tests).
5. **The 16384 refusal** is the pin author's addition (H21; the village's colour is 4200 × 4300).
   Option B: drop it (one test).
6. **v0.6.0-04's pin superseded.** `test_m4_02_surroundings_fixture.py` is re-pinned here (one test
   compares key by key), so v0.6.0-04's byte-identity command reports that file once 08 lands; the
   alternative was a separate top-level manifest block for the colour (07's top level changes).
