## Open questions for the session

1. **The panel's name for the far terrain.** Design §3 says "the error panel's entry
   `Surroundings`". (A, taken) `SURROUNDINGS_WHAT := "the far terrain"`, a phrase like every
   other entry ("mattini cannot show the far terrain."); (B) "Surroundings" literally ("mattini
   cannot show Surroundings."). One constant and five pinned strings in three test files.
2. **How the far colour is credited.** Design §2: "the far colour adds no new line unless the
   editions differ". (A, taken) the line `swissimage <colour edition>, <colour attribution>`, under
   the photo's dataset name (`FAR_COLOUR_CREDIT`), so it merges with the photo's line when the
   edition and the attribution agree and stands alone when either differs (the complete world's
   synthetic attribution: alone); (B) no colour line at all when a photo block was read with the
   same edition, else `swissimage_far <edition>, …`. A is one constant; B needs the photo in
   `_credited`'s colour branch and changes one test.
3. **The trees' control figure.** (A, taken) the 40 km far plane moves `RENDER trees`' "x and z
   exchanged" control from -0.2128 to -0.2126, recorded, no override; (B) `render_trees.gd` sets
   its camera's far to 20'000 m in its view (one line in a pinned render script; the line then
   the head's digit for digit). The PASS figure 0.8637 is unchanged either way.
4. **The complete world's NaN layout** does not follow the pipeline's cut rule for its own area
   (the area lies between 3 km grid vertices, so the rule would give no NaN and the far mesh
   would cover the near terrain); (A, taken) the fixture's six NaN vertices kept, the box moved so
   they surround the area, labelled test data; (B) a heights file of this world's own, built by
   the rule at a spacing fine enough to put NaN inside a 20 × 11.5 m area (≤ 5 m: thousands of
   vertices over any box that also keeps the far mesh out of the render checks' views), with its
   own colour: a new fixture, more design data.
5. **The export's line count** (v0.6.0-10): until -10 lands, a real export prints the far
   terrain's line beyond step 6's `7 +` count; step 6 searches each expected line in order, so
   it passes (read in `tools/export.sh`, not run here). If the session wants -09 and -10 to land
   together, say so in the plan.
