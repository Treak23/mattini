## Open questions for the session

1. **The record does not name the Python.** `docs/releases/v0.5.0.md` names neither 3.13.14 nor
   the zlib; the pin's source is the real run's job log (line 221) and the dry run's (R1-CD-04).
   Recommendation: keep 3.13.14 (both runs, and design's bytes reproduced on it, H31); the 0.6.0
   record copies the new step's two log lines (the interpreter and its zlib). Alternative: pin
   the container's 3.13.18 instead (no GitHub run proves it; the runner must download it).
2. **`UV_PYTHON_PREFERENCE: only-managed`** is the pin author's (R1-CD-04's fix shape), not in the
   session's item list. Easier to undo than to add: one env line and one assert. Alternative:
   rely on `UV_PYTHON` alone plus the version refusal (a system 3.13.14 on a future image would be
   taken, its zlib unknown, and the pipeline's byte checks would refuse it on release day).
3. **The ancestry fetch is unauthenticated** (`persist-credentials: false` stays). Works while the
   repository is public; if it turns private the step fails closed (the run stops before any
   download). Alternative: pass `GITHUB_TOKEN` to that one fetch (an `http.extraheader`), which
   widens what the token touches; or `gh api …/compare/main...<sha>` (status `behind` or
   `identical`). Recommendation: keep it; revisit only on a visibility change.
4. **v0.6.0-10 (lane A) also edits `release.yml` and `test_release_workflow.py`.** It is "after
   03" in design §6, so its pins must be re-cut on this batch's result (this record's SHA-256 of
   the file), never on today's live file. The plan's hot-file order should name it.
5. **The `uv sync` moved** from "uv, from the pins" into the new Python step (so no sync runs
   before the pinned interpreter exists). The pins require only that the install precedes every
   sync; a builder may instead keep the step and add `--python`. Recommendation: as rehearsed.
6. **§C's line keeps 0.5.0's pair** (326124, `f68275a1…`); 0.6.0's pair is the session's at the
   integration rehearsal (design §5). The test reads whatever pair the line holds.
