## Open questions for the session

1. **The real run is not a builder gate.** No `download regio` (v0.6.0-02) and no lock entry
   (v0.6.0-01) on `main` while this lane-B batch builds; the brief leaves the real village to
   v0.6.0-07's gate through the CLI. Option B (harder to undo, more evidence now): give the
   builder a driver that lays out the session's downloaded zips (as this rehearsal did) and runs
   `build_surroundings` with the committed configs. Taken: A.
2. **A square lacking samples** takes the mean of those it holds (design §1's "n"), pinned by
   one test. Option B: refuse any kept vertex whose square is not complete ((s / r)² samples). No
   real tile lacks a sample in the window (design §0), so either changes no byte of the village.
   Taken: A (the design's formula as written).
3. **The config refuses any key but M4-02's seven**, so v0.6.0-06 re-pins
   `test_m4_02_surroundings_config.py` and the step's checker to add `colour`. Option B: accept
   and ignore a `colour` key now (an unchecked key; weaker). Taken: A.
4. **The offset** is subtracted in float64 after the exact quotient (design §1 does not say where
   the offset goes; M4-02 said "computed in 64-bit and rounded once"). The exact alternative
   (`(sum_cm − 100·n·offset_cm) / (100·n)`) gives the same float32 on the fixture and the village
   (offset 0) and differs in general only at a float32 midpoint, which a rational of
   denominator 100·n cannot hit closely enough. Taken: the float64 subtraction, pinned in the
   docstrings and the fixture's oracle (which computes it exactly, in Fractions).
5. **The fixture's committed `generated/manifest.json`** (M4-07's form) is re-cut here (its
   `sha256` line only) and pinned by one test, so no committed file carries M4-02's heights.
   `test_m4_09_manifest.py`'s docstring says it "stays as it is" (about 0.4.0-07 and 0.5.0-02,
   not this brief). Option B: leave it to v0.6.0-07, which writes the real block. Taken: A.
6. **The red is a collection error**, as in 0.5.0-01: every pinned test file imports the new
   module.
7. **The line number** is pinned as `line <k>` with the header as line 1 (design §1 says
   "naming the tile and line"); the text itself is also required in the message.
