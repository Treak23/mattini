## Open questions for the session

1. **The shape of the absent cells** (design §2: "recorded in the lock as absent"). Pinned: an
   `absent` list beside `tiles` in the entry (and in provenance.json), sorted, disjoint. Option
   B: `tiles` maps an absent cell to `null` (one object, no second key), which changes
   `validate_lock`'s tile check and the colour step's reading. The list is easier to undo (B is
   a rewrite of one key) and leaves every tile entry {file, sha256} as the photo's.
2. **Which STAC names to read.** Design §2 says `checksum:multihash` and `eo:gsd 2.0`; those are
   the v0.9 API's (design measured on v0.9). The pipeline reads v1 (`file:checksum`, `gsd`).
   Pinned: v1 through the existing `_published_asset`, the same checksums (two ways). If the
   session wants the resolution checked from `gsd` as well as from the asset's name, a test
   and a mutation row are to add; today the name's `_2_` is the check.
3. **The concurrency, 8.** Pinned: `FARPHOTO_WORKERS == 8` and a barrier proving eight at once,
   for the reads and the fetches; no test bounds the real number of requests in flight
   beyond the constant's value. Option B: a
   lower number for politeness to swisstopo (4: the times double). Option C: no constant pinned,
   only the barrier.
4. **The count line and the provenance's `absent`** are the session's words: `<n> tiles
   verified, <f> fetches, <a> cells without an item`. v0.6.0-02's open question 3 (one unit in
   `DATASETS`) is answered by a farphoto-only tail in `_download`.
5. **The credits** (design §2): `test_release_notes.py` now skips a dataset that shares
   collection, edition and attribution with an earlier one, so `swissimage_far` adds no line to
   tools/release_notes.md. Option B: credit it as `swissimage_far 2023, © swisstopo` (a line in
   the notes, SPEC_LINES gains it); then the pause screen (v0.6.0-09) would have to show it too
   or the notes and the game differ.
6. **SPEC §13 row 59 says "a plain shading elsewhere"**, design §2 fills the uncovered cells by
   altitude band from the photo's own colours. Not this brief's (v0.6.0-06's), but the record
   of the 586 absent cells pinned here serves either; the session may want to reconcile the
   words before v0.6.0-06's pins (the SPEC outranks the design).
7. **The lock's growth:** 249'517 bytes (from 11'327), 5475 added lines; the owner lifted the
   size limit for 0.6.0. Every `lock` command rewrites the whole file (sorted), so later locks
   keep it.
8. **`download farphoto` reads 1806 items every run** (28.9 s with nothing to fetch). It is the
   price of refusing a new item in an absent cell at download (design §2). Option B: refuse only
   at the next `lock farphoto` (the fit then fails against the colour's `computed_for`); then
   rows 9 and 10 change and the download reads 1220.
9. **Gaps the prover should look at** (brief decision 14): the reader before the first request
   (only a refused config shows it); the cancelling of work after a refusal; the shared fetch
   code.
