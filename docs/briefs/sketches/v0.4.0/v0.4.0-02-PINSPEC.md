## The decisions as pinned (the session's 1 to 7; R = measured here)

- The block's `flow` is exactly {cell_m, columns, encoding, file, pixels_sha256, rows, sha256}
  (v0.4.0-01's `FLOW_KEYS`); `cell_m` a number equal to 2 (`FLOW_CELLS = [2.0]`; "2" refused);
  `encoding` `"downstream-bearing-1.5deg"` through `ManifestValue.differs` (a number refused, never
  a runtime error, brain.md H26); `columns` and `rows` whole numbers ≥ 1 that fit the box within
  `BOX_TOLERANCE_M` (the flow covers the classes' box; `rect()` places both); `file` a plain
  relative path; `sha256` and `pixels_sha256` 64 hex digits.
- Read order: the classes as today, then the flow: presence, the PNG's SHA-256 against
  `flow.sha256` BEFORE decoding, `load_png_from_buffer`, L8 of exactly `columns × rows` (a 15 × 20
  PNG for a 20 × 15 grid refused), the decoded bytes against `flow.pixels_sha256` (as the classes'
  `pixels_sha256`; the session's decision 1 says "as for the classes PNG"), then every code ≤ 240.
  Every file message ends with `ReleaseBuild.file_hint("python -m mattini surfaces")`.
- The colours: one table of 241 entries, made once per read through the WorldConfig:
  ```gdscript
  var bearing := deg_to_rad((k - 1) * FLOW_STEP_DEG)
  var local := world.to_local(
  	world.origin_e + sin(bearing), world.origin_n + cos(bearing), world.height_offset
  )
  var x: float = local.x
  var z: float = local.z
  var length := sqrt(x * x + z * z)
  R = roundi(128.0 + 127.0 * x / length); G = roundi(128.0 + 127.0 * z / length); B = 255
  ```
  code 0 (128, 128, 0). The texture: `Image.create_from_data(columns, rows, false,
  Image.FORMAT_RGB8, bytes)`, rows from the north as the PNG, no mipmaps;
  `ImageTexture.create_from_image`. The linear filter is the shader's sampler (03).
- `flow_at(x, z)`: column `floori((x − x0) / flow_cell_m)`, row `floori((z − z0) /
  flow_cell_m)`, half-open; outside `Vector2.ZERO`; else `Vector2((R − 128) / 127.0, (G − 128) /
  127.0) * (B / 255.0)` from the texture's own bytes (so code 0 is the zero vector).
- Public members: `flow_cell_m`, `flow_columns`, `flow_rows`, `flow_texture` (ImageTexture),
  `flow_at`. The tests reach them by name (`has_method`, `call`, `get`) so that the script loads
  before the change and fails by their names.

## Design values, each two ways

### The colour of every code (the 723 bytes behind the texture)

Way 1: `rh/work02/colours.py`, the GDScript arithmetic emulated step by step in Python (IEEE
doubles; `math.radians`, `math.sin`, `math.cos`; the origin added and subtracted in doubles; the
narrowing of WorldConfig's `Vector3` to float32 with `numpy.float32`; the length and the division
in doubles; Godot's `roundi`, half away from zero), for the fixture's origin (2'700'000 /
1'200'000) and the village's (2'623'000 / 1'096'000): identical tables. Way 2: Godot itself (the
throwaway's table, printed by a probe through three WorldConfigs: the surfaces fixture's, the real
village's, the terrain fixture's): identical to way 1 at all 240 codes for all three. The table's
SHA-256 (723 bytes, code 0 first): `ef1471daa85975e29fd061db6c9b91ced010ec17ae518c76faa4a96ef962c1be`,
both ways. The test pins it as the SHA-256 of a synthetic 20 × 15 flow's texture (cell i holds
code i for i ≤ 240, then 0): `a0c149faee09150cc86f14ddc7381c4fea7f8ee2c81b3e60a0a49602a0dcd373`
(900 bytes; Python and Godot).

Way 0, exact (60-digit decimal arithmetic, `colours.py` way A): at 232 of the 240 codes the exact
128 + 127 sin b and 128 − 127 cos b lie at least 0.009 from a rounding boundary (the nearest: code
10's G, 4.50902), some 10³ times any float error on this path, so every byte there is the exact
value rounded. At **eight codes the exact value is a tie**: sin or cos of the bearing is ±1/2
(codes 21, 41, 81, 101, 141, 161, 201, 221: 30°, 60°, 120°, 150°, 210°, 240°, 300°, 330°), so R or G
is exactly 64.5 or 191.5. The pinned arithmetic decides them: the other component, narrowed to
float32 by `to_local`'s `Vector3` (cos 30° = 0.8660254037844387 becomes 0.8660253882408142), makes
the 64-bit length 0.99999998…, so the tied component lands 8.5e-7 outside the tie and rounds to
64 or 192: 128 ± 64 at all eight, a direction and its reverse decoding to exact opposites. A
float32 normalisation (`Vector2(local.x, local.z).normalized()`) lands exactly on the tie and
Godot's `roundi` gives 65 at codes 41, 141, 201 and 221 (mutation row 15: three tests fail). The
visible difference is 1/127 (0.45°) on four bearings: none for the owner; the pins hold the
arithmetic so that the bytes are one value. Accepted as the session's ruling, 2026-10-27 (the
64-bit normalisation and the tie rule; the brief's Decision 4 credits it so).
