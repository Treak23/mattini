## Goal

The river's ripples move downstream along each stream's own course. `TerrainLoader` hands the
terrain shader the SurfaceGrid's flow texture as `water_flow`, placed by the classes' own rectangle
(the flow grid covers the same box). The photo shader decodes the local downstream direction from
it and drifts both ripple maps along it, map a (2 m tiles) at 0.8 m/s and map b (3.4 m tiles) at
0.5 m/s, each read in two phases half of a 2 s period apart that crossfade (the flowmap
technique, needed because the direction varies by place); a smooth phase field keeps the restarts
from pulsing in unison; and since 3600 s holds a whole number of 2 s periods, nothing jumps when
TIME wraps. Three pinned tests hold the shader's lines, the period against the rollover, the
comments, the placement line and the loader's seam. The gate's render checks print exactly the
numbers they print today.

Production code is `main` once v0.4.0-02 has landed. The pin author rehearsed this brief in the
clone v0.4.0-02's rehearsal left (2026-10-27: `main` at `4d4cc63` with v0.4.0-01's and v0.4.0-02's
pins and throwaways): the pins red on v0.4.0-02's shader and loader, green on a throwaway written
from the Decisions below, the full gate, all sixteen mutation rows both ways, and a motion probe
of the drift under Compatibility and software Forward+. Every number marked "rehearsal" was

3. **The water's uniforms** (the session's decisions 2 and 3; replaces 0.3.1's `water_drift`).
   The `group_uniforms water;` block becomes exactly (CODE lines exact; the comments may be worded
   otherwise only if they stay true AND keep the words the pinned comments test needs: within the
   group's comment lines "downstream", "swissTLM3D" and "look value"; nowhere in the file
   "drifting apart", "drifts against", "no net direction" or "water_drift"):
   ```glsl
   group_uniforms water;
   // The water's ripples drift downstream along swissTLM3D's watercourse lines (briefs v0.4.0-01 to
   // v0.4.0-03; SPEC §13 row 53). Two NoiseTexture2D normal maps (TerrainLoader makes them; no
   // file): map a tiles every water_scale_a_m and drifts at water_speed_a, map b tiles every
   // water_scale_b_m and drifts at water_speed_b, both along the flow. water_flow is SurfaceGrid's
   // flow texture, one RGB8 texel per 2 m cell of the classes' own box (placed by surfaces_rect):
   // the downstream direction in local (x, z) of the nearest drawn stream, decoded as
   // (rg · 255 − 128) / 127 · b, filtered linearly; b is 0 where no stream is near, and the sampler
   // unset reads black (hint_default_black), no drift too. The flow varies by place, so each map is
   // read in two phases half a period apart, each moved downstream for one period water_phase_s and
   // then restarted where its weight is 0, the two crossfaded (the flowmap technique); 3600 s, Godot's
   // TIME rollover, is a whole number of periods, so nothing jumps when TIME wraps.
   uniform sampler2D water_normal_a : hint_normal, filter_linear_mipmap, repeat_enable;
   uniform sampler2D water_normal_b : hint_normal, filter_linear_mipmap, repeat_enable;
   uniform sampler2D water_flow : hint_default_black, filter_linear, repeat_disable;
   uniform float water_scale_a_m = 2.0;
   uniform float water_scale_b_m = 3.4;
   // The crossfade's period (s), a look value; 3600 / water_phase_s must stay whole (a pinned test).
   uniform float water_phase_s = 2.0;
   // The drift speeds along the flow (m/s): look values, not measured (swissTLM3D gives no speed).
   uniform float water_speed_a = 0.8;
   uniform float water_speed_b = 0.5;
   uniform float water_normal_strength = 0.35;
   // On water the photo's colour is multiplied by this: the photo's own river, a little darker.
   uniform float water_albedo = 0.9;
   group_uniforms;
   ```
   (Indentation in the shader is tabs.) `const float WATER_ROUGHNESS = 0.3;` stays.
   - `water_flow` is declared `hint_default_black` (the session's ruling, 2026-10-27, on the
     02 × 03 seam the integration rehearsal found): in Godot 4.6.3 a `sampler2D` with no
     `hint_default_*` that is never set gets the WHITE default texture in both renderers, which
     decodes as (1, 1), a south-east drift at about 1.4 times both speeds; with the hint an unset
     sampler reads black, which decodes as no drift, as the group's comment says (probe under
     Compatibility: `unset reads (1.0, 1.0, 1.0, 1.0)` without the hint, `(0.0, 0.0, 0.0, 1.0)`
     with it). The loader still sets it always (Decision 2). No `source_color` (a direction is a
     number, brain.md H21).
   - Keep the name `water_normal_strength`: the gate's `render_photo.gd` sets it to 0 by name.
   - Why 2 s: 3600 / 2 = 1800 whole, so `fract(TIME / water_phase_s + …)` is continuous across the
     wrap (Godot 4.6.3: TIME = fmod(the frames' time, `rendering/limits/time/time_rollover_secs`,
     default 3600) in both renderers; `game/project.godot` sets no rollover). Rehearsal, two ways:
     exactly 1800 periods; a float32 emulation across the wrap at 60 fps steps the phase by
     0.0083 per frame on both sides (0.3.1's map b: (0.80, 2.20) m, i.e. (0.80, −1.20) m modulo the
     3.4 m tile, both ways).
4. **The phase field, `water_phase(xz)`** (the session's decision 3: smooth, no fract, varying over
   10 m or more, e.g. a sum of two sines; a look value). Insert it **directly after
   `water_weight`'s closing brace, before the comment `// The rock texture projected…`** (above
   `// Varyings & Types`, which the pinned `test_m3_09_photo_shader.gd` requires to stay identical
   to the clay shader from there on), exactly:
   ```glsl

   // The water's phase offset at (x, z), in periods: two sines across the ground (wavelengths about
   // 23 m and 37 m), together within ±0.5 of a period and smooth (no fract, so no seam), so that the
   // two phases' restarts do not pulse over the whole river at once. A look value, never measured.
   float water_phase(vec2 xz) {
   	return 0.25 * sin(dot(xz, vec2(0.21, 0.17))) + 0.25 * sin(dot(xz, vec2(-0.11, 0.13)));
   }
   ```
   Rehearsal, two ways: wavelengths 23.26 m and 36.90 m; the largest gradient 0.0806 periods per
   metre (analytic: 0.25 · max(|k1 + k2|, |k1 − k2|); numeric over the village's local box: the
   same), so the pattern is stretched by at most 13 % (map a, 1.6 m per period) and 8 % (map b);
   the largest sine argument in the village 590 rad, float32's step there 6.1e-05 rad.
5. **The water rule in `fragment()`** replaces today's from `// Water: the photo's colour ×
   water_albedo, roughness WATER_ROUGHNESS, two ripple maps` to its closing brace, exactly:
   ```glsl
   	// Water: the photo's colour × water_albedo, roughness WATER_ROUGHNESS, its weight eased over
   	// 1 m at the bank; both ripple maps drift downstream along the flow, each read in two phases
   	// (p0, p1, half a period apart) whose weights (w0, w1) sum to 1 and are 0 at each restart.
   	float w_water = water_weight(xz);
   	if (w_water > 0.0) {
   		vec4 t = texture(water_flow, (xz - surfaces_rect.xy) / surfaces_rect.zw);
   		vec2 flow = (t.rg * 255.0 - 128.0) / 127.0 * t.b;
   		float p0 = fract(TIME / water_phase_s + water_phase(xz));
   		float p1 = fract(p0 + 0.5);
   		// Each map's offset over one whole period, downstream (m).
   		vec2 da = flow * water_speed_a * water_phase_s;
   		vec2 db = flow * water_speed_b * water_phase_s;
   		// The pattern at xz is the one from (xz - offset): it moves along +flow.
   		vec2 ua0 = (xz - p0 * da) / water_scale_a_m;
   		vec2 ua1 = (xz - p1 * da) / water_scale_a_m;
   		vec2 ub0 = (xz - p0 * db) / water_scale_b_m;
   		vec2 ub1 = (xz - p1 * db) / water_scale_b_m;
   		vec2 dxa = ddx_xz / water_scale_a_m;
   		vec2 dya = ddy_xz / water_scale_a_m;
   		vec2 dxb = ddx_xz / water_scale_b_m;
   		vec2 dyb = ddy_xz / water_scale_b_m;
   		vec3 na0 = unpack_normal(textureGrad(water_normal_a, ua0, dxa, dya));
   		vec3 na1 = unpack_normal(textureGrad(water_normal_a, ua1, dxa, dya));
   		vec3 nb0 = unpack_normal(textureGrad(water_normal_b, ub0, dxb, dyb));
   		vec3 nb1 = unpack_normal(textureGrad(water_normal_b, ub1, dxb, dyb));
   		float w0 = 1.0 - abs(2.0 * p0 - 1.0);
   		float w1 = 1.0 - abs(2.0 * p1 - 1.0);
   		vec2 ripple = (w0 * (na0.xy + nb0.xy) + w1 * (na1.xy + nb1.xy)) * water_normal_strength;
   		bump = mix(bump, vec3(ripple.x, 0.0, ripple.y), w_water);
   		albedo *= mix(1.0, water_albedo, w_water);
   		roughness = mix(roughness, WATER_ROUGHNESS, w_water);
   	}
   ```
   - The flow is placed as the classes are: uv = (xz − rect.xy) / rect.zw puts texel (c, r)'s
     centre at the centre of 2 m cell (c, r), rows from the north, as `SurfaceGrid.flow_at` reads
     it; the sampler's linear filter blends the four nearest cells. This is the brief's placement
     line (tier 1).
   - The weights sum to 1 (w0 + w1 = 1 for every p0) and each is 0 when its phase restarts, so the
     restart is invisible; the phase field shifts where in the period each point is.
   - TIME appears on that one line only (the pinned rollover test counts it).
   - The texture() call sits inside the branch: the flow texture has no mipmaps and its sampler
     no mipmap filter, so no derivative is needed; the ripples keep `textureGrad` with the
     derivatives taken outside any branch, as before.
