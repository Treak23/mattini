## Goal

While the pause screen is open, the game draws at most 15 frames a second instead of the
project's 60: the 3D scene behind the pause screen keeps drawing, about a quarter as often
(FB-007: the owner's laptop GPU ran flat out, also in the Esc menu). Closing the pause screen,
by the pause key, by Resume or by `toggle_pause()`, gives back the project's cap, and so does
the main scene leaving the tree while paused. In an exported build the data packs missing
beside the executable are listed on the red error panel, right under its first line, before
any refusal (FB-005: with `mattini-photo.pck` moved aside, the log named the pipeline and not
the pack, and nobody looked at the screen; 0.3.0's panel, read from the code, names no single
pack either); when nothing else is refused the panel still opens, its first line then "mattini
cannot find every data pack.", its fix the release folder. The panel's "is this an exported
build" comes from `ReleaseBuild.is_exported()` (brief v0.3.1-03), no longer from
`OS.has_feature("template")` in `main.gd`. Outside an export nothing changes. All the code lives
in `game/scripts/main.gd`, under the exact names M4-10 uses, so M4-10's own pinned tests stay
valid on top of it later.

Not this brief: the clock, the time keys, the clock label, the moved buttons, the sky, the far
mountains, the capture mask and every other part of M4-10 (a later release); the project's cap
of 60, the flushed log and MSAA (v0.3.1-02, landed); `ReleaseBuild`, `DataPacks.EXPECTED_PACKS`
and `missing_pack_errors` (v0.3.1-03, landed); `tools/export.sh`'s pack checks (v0.3.1-04).

## Commands you will use

Keep every scratch file outside the worktree and give every Godot run you start yourself its
own `XDG_DATA_HOME` (H9; `tools/gate.sh` makes its own). **Your shell keeps no variables,
functions or working folder between tool calls**: create the scratch folder once (`mktemp -d`),
write its path down, and put that literal path wherever this brief writes `$S`; the same for
the base sha wherever it writes `$BASE`. A command run with an empty `$S` writes into `/`. Run
every command from your worktree's root; for the clean worktree of the batch gate, begin that
same call with `cd <its literal path> &&`. Define no shell function to reuse: write each command
out whole.

One test script alone (`<script>` is the file name, for example
`test_pause_cap_and_pack_panel.gd`; called "the single-script run of `<script>`" below):

```
XDG_DATA_HOME="$S/xdg" godot --headless --path game -s addons/gut/gut_cmdln.gd \
  -gtest=res://tests/<script> -gexit -gconfig= > "$S/<script>.log" 2>&1
```

Read a run by its lines, not by Godot's exit status alone: each test's name (`* test_…` as it
runs; `- test_…` in the run summary, which repeats a failing test's failures under its name), its
`[Failed]` lines (GUT prints none for a passing test, and no `[Passed]` line at all), its
`<n>/<m> passed.` line, its `---- ` summary and any `SCRIPT ERROR`, `ERROR` or `[ERROR]` line:
`grep -a -n -E '[*-] test_[a-z0-9_]+$|\[Failed\]|passed\.|SCRIPT ERROR|^ERROR|\[ERROR\]|Ignoring script|---- ' "$S/<script>.log"`.
GUT colours its lines in a raw log (an escape code stands before `---- `, `[Failed]`, `[ERROR]`
and some test-name lines), so none of those is anchored with `^`; Godot's own `ERROR` lines are
not coloured.
In a fresh worktree run `XDG_DATA_HOME="$S/xdg" godot --headless --path game --import` once before
the first test run, and again after the copy of step 3.
