Status: DONE (7c93b4ee9f8a7dca8d78d062d2855e57afa528e2)

Written by the release session of 0.5.0 (`docs/roles/DESIGN.md`); built by one fresh builder
agent under `docs/roles/BUILD.md`. The owner's 1a (`docs/history/blocked/2026-10-29-2.md` item 1):
a release is built by a GitHub Actions workflow on a GitHub-hosted runner from the pinned inputs and
attached to a draft Release that the owner publishes; `dist` stays as the rollback record of 0.1.0
to 0.3.1. Tier 2: tools, words, licence and attribution (WORKFLOW §Review policy); nothing in the
pipeline, the world or the game changes.

## Goal

`.github/workflows/release.yml`, started by hand with a commit, a version and the manifest pair the
release's plan names, builds that commit on a GitHub runner exactly as the release gate builds it in
a container: the pipeline from the pinned inputs (each step comparing with design's values before it
writes), the manifest pair, `tools/export.sh`, then docs/RELEASE.md §C's runtime checks as a script
with an exit status (`tools/release_checks.sh`), then two archives of five files each and their
checksums (`tools/release_pack.sh`). A dry run (the default) keeps the archives as a workflow
artifact for three days; a real run makes a draft Release with the archives, `SHA256SUMS` and notes
rendered from a committed template that carries every credit the game shows. The Godot pin gets one
home, `tools/pins.sh`, which the session-start hook and the workflow both source.

The pin author rehearsed this brief in a clone of `main` + v0.5.0-01's and v0.5.0-02's rehearsals
(2026-10-30): the pins red on that tree, green on a throwaway implementation, the full gate, every
mutation row. Every number marked "rehearsal" was measured there. The pin author's record is
`docs/briefs/sketches/v0.5.0/v0.5.0-06-PINSPEC.md`, committed by the session; you do not need it.
**Nothing here was run on GitHub.** The workflow's first run on GitHub (a dry run, then the live
one) is the session's step after this batch lands on `main` (a `workflow_dispatch` runs only a
workflow file on the default branch), not a builder gate.

1. **The workflow** (owner; session): `.github/workflows/release.yml`, `name: release`.
   - Trigger `workflow_dispatch` only. Inputs: `sha`, `version`, `manifest_bytes`,
     `manifest_sha256` (required strings) and `dry_run` (boolean, default true: a run nobody set
     creates no Release). The two manifest inputs are the pin author's (the pair changes with every
     release that changes a generated file, and the release's plan names it; a committed file would
     need a value nobody has measured when this batch lands).
   - `permissions: contents: write` at the top and nothing else; no job widens it. The only token is
     the runner's `GITHUB_TOKEN` (Hard Rule 1); no other `secrets.` is named.
   - One job on an Ubuntu runner (the rehearsal used `ubuntu-24.04`), `timeout-minutes` between 60
     and 360 (the rehearsal: 180), `defaults: run: shell: bash` (bash with `-o pipefail`, so a `| tee`
     keeps a failure).
   - The inputs reach the shell only through the job's `env` (`RELEASE_SHA`, `RELEASE_VERSION`,
     `MANIFEST_BYTES`, `MANIFEST_SHA256` = `${{ inputs.<name> }}`); no `${{ … }}` inside a `run:`
     (an input is never spliced into a command). The first step checks them (40 lower-case hex, X.Y.Z,
     a positive whole number, 64 lower-case hex) and exits 1 on any other value, before checkout.
   - Only `actions/checkout@v4` (`ref: ${{ inputs.sha }}`, `persist-credentials: false`) and
     `actions/upload-artifact@v4` are used; no third-party action. A step after checkout and
     before Godot requires `git rev-parse HEAD` to equal `RELEASE_SHA` (pinned by running it in a
     scratch repository: another commit exits non-zero).
   - Nothing lets a failure through (the release's checkers, 2026-10-30): no `continue-on-error`
     anywhere; no run text with `|| true`, `|| :`, `|| exit 0` or `set +e` (or `set +o errexit`);
     no step `if` with `always()`, `failure()` or `cancelled()`.
2. **The order of the steps** (session; RELEASE.md §C): the inputs; checkout; free disk (the runner's
   preinstalled toolchains this build does not use); Godot 4.6.3 from `tools/pins.sh`, its zip
   checked against `GODOT_SHA256` with `sha256sum -c` (`GODOT_SHA256` piped into `sha256sum -c`
   before `unzip`: pinned), then `GODOT` and `PATH` set for later steps;
   uv `==$UV_VERSION` from `tools/pins.sh` and `uv sync --project pipeline --frozen` (every `uv
   sync` and `uv run` of the workflow is `--frozen`: pinned); the downloads
   (`python -m mattini download` terrain, buildings, photo, surface, tlm: about 6 GB with the
   national swissTLM3D); the pipeline in this order: `terrain, buildings, photo, roofs, surfaces,
   trees, shadows, sky, manifest` (each compares with design's values before it writes; `shadows`
   is v0.5.0-02's command); the manifest pair (`wc -c` equal to `MANIFEST_BYTES`, `sha256sum -c`
   with `MANIFEST_SHA256`, RELEASE.md §C's command; the pinned test runs the step as GitHub's
   `shell: bash` does, `bash -e -o pipefail`: exit 0 for the pair, non-zero for another size or
   another SHA-256, so its failure fails the run); the first import (the extension list first, as
   `tools/gate.sh` writes it); `tools/export.sh` (its log kept, and its step 2b's "…, as written
   here" line found in it by a `grep` after it: pinned); `tools/release_checks.sh`; `tools/release_pack.sh "$RELEASE_VERSION"
   "$RELEASE_SHA"`; then
   - dry run: `actions/upload-artifact@v4`, `if: ${{ inputs.dry_run }}`, `retention-days: 3`, the
     two archives, `SHA256SUMS` and the notes;
   - otherwise (`if: ${{ !inputs.dry_run }}`), with `GH_TOKEN: ${{ secrets.GITHUB_TOKEN }}`: `gh
     release create "v$RELEASE_VERSION" --draft --target "$RELEASE_SHA" --title "mattini
     $RELEASE_VERSION" --notes-file build/release/release-notes.md` and the two archives and
     `SHA256SUMS`. Never `--latest`, never `gh release edit` or `upload`: the owner publishes.
   `tools/export.sh` is unchanged: its 100 MiB limit stays (Releases lift it only for M5; the
   Windows executable is 198 KB under it, H15). `SHA256SUMS` is printed in the log in every run.
3. **`tools/release_checks.sh [<linux build folder>]`** (session: RELEASE.md §C's hand checks as a
   script; default `build/linux`). One `release check: <name>: PASS|FAIL <what it found>` line per
   check; every check runs whatever the one before found; exit 0 only when all five pass, else 1;
   last line `== release checks: all passed` or `== release checks: <n> failed`. Every start is
   headless with `user://` in a scratch folder (`XDG_DATA_HOME`) and a timeout. In order:
   1. `stars`: `mattini.pck`'s directory (Godot 4.6.3's pack format 3, read as step 4c reads it)
      holds `sky/stars.csv` with `game/sky/stars.csv`'s size and MD5. Its line quotes the
      reader's own words only: the reason for either verdict on stdout, uv's stderr not captured
      into it (the release's checkers, 2026-10-30: the rehearsal's `2>&1` put the container's uv
      deprecation warning into the PASS line; pinned by
      `test_uv_s_own_words_stay_out_of_the_stars_line`, a stand-in uv that speaks on stderr);
   2. `frame cap`: `--headless --print-fps --quit-after 600` prints `Project FPS: 60`, exit 0, no
      `ERROR`/`SCRIPT ERROR` line, one `mattini <version>: data pack <name> loaded` line per
      `mattini-*.pck` beside the executable and further startup lines after them; its `mattini
      <version>: ` lines are what check 5 expects;
   3. `override.cfg`: one written beside the executable (`[application]` `config/version=
      "0.0.0-override-check"`, `[rendering]` `anti_aliasing/quality/msaa_3d=0`) makes the startup
      lines show the marker; it is removed after; an `override.cfg` already there fails the check
      and is not touched;
   4. `missing pack`: with `mattini-photo.pck` moved aside, the line `ERROR: DataPacks: the data pack
      mattini-photo.pck (the aerial photo) is missing from <the build folder's real path>: download
      the release folder again` and a line `ERROR: PhotoGrid: …download the release folder again`;
      the pack goes back and its SHA-256 is unchanged;
   5. `live log`: started with no `--quit-after`, its output and `user://logs/godot.log` hold every
      startup line of check 2 while the process is alive (within 120 s, or
      `RELEASE_CHECKS_LIVE_TIMEOUT_S` seconds when the environment sets it: the pins set 20, so a
      log that never fills fails in 20 s); then it is stopped by its PID.
   The build folder is left as it was found after a pass and after a failure (a trap restores the
   pack and removes the written `override.cfg`).
4. **`tools/release_pack.sh <version> <sha> [<build> [<out>]]`** (session; the archives' shape is the
   pin author's): defaults `build` and `build/release`. It writes `mattini-<v>-linux.tar.gz` (the
   five Linux files under `mattini-<v>-linux/`), `mattini-<v>-windows.zip` (the five Windows files
   under `mattini-<v>-windows/`), `SHA256SUMS` and `release-notes.md`, and prints `SHA256SUMS`.
   - The five files: Terrain3D's library, `mattini-photo.pck`, `mattini-terrain.pck`, `mattini.pck`,
     the executable (dist's five). Each archive holds those five only (no folder entry), in name
     order (C locale), byte for byte; the time of every entry is `SOURCE_DATE_EPOCH`, else the
     commit time of `<sha>` (`git show -s --format=%ct`); in the tar owner and group 0, mode 0755
     for `mattini.x86_64` and 0644 for the rest; the zip's times in UTC. The same build gives the
     same bytes whatever the files' times and the time zone.
   - `SHA256SUMS`: `sha256sum` lines of the two archives and of the ten files by their path inside
     the archives, sorted by path (C locale); `sha256sum -c SHA256SUMS` passes beside the two
     unpacked archives.
   - `release-notes.md`: `tools/release_notes.md` with `@VERSION@`, `@SHA@` and the line
     `@SHA256SUMS@` (replaced by the file's lines) filled; a placeholder left is refused.
   - Refused with exit 1, naming the cause, nothing written into `<out>`: a version other than
     `game/project.godot`'s (named with it), a version not X.Y.Z, a sha not 40 lower-case hex, any of
     the ten files missing (named), a `mattini-*.pck` in a build folder that the archive would leave
     out (named), no `SOURCE_DATE_EPOCH` and no such commit.
