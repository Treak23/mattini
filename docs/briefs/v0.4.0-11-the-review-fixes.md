## Goal

1. The gate's render checks give the same numbers every run again. Since v0.4.0-08 the main scene's clock runs
   while `render_photo.gd` and `render_trees.gd` wait for frames, so the sun moves between runs and
   `RENDER trees` moved in its fourth decimal (0.8658 to 0.8666 over the release's runs). Both scripts stop the
   main scene's `_process` right after adding it, so the sun stays at the start moment `_ready` placed it.
2. In an exported build the sky block's refusals (`SkySite`) end like every other reader's file message: "download
   the release folder again", not "run python -m mattini sky" (a command a player cannot run); outside a release
   they still name the command (review finding F3).
3. Words that describe 0.3.1 or claim more than the code does are corrected (Hard Rule 2): the list in Decision 3.

## Decisions already made

1. **The render scripts stop the clock** (the plan's seam 5; the session's ruling on v0.4.0-08, 2026-10-29):
   in both `render_photo.gd` and `render_trees.gd`, directly after `root.add_child(main)` and before the first
   `await process_frame`, call `main.set_process(false)` with a comment that says why (the game clock runs in
   `_process`; the check wants one sun; `_ready` has already placed it at the start moment). Nothing else about
   the scripts changes. Expected: `RENDER photo` and `RENDER classes` unchanged digit for digit
   (0.9752 and 70039 of 70180 at the head you start from; measure them first); `RENDER trees` takes one value
   (it was 0.8659 to 0.8666) and **repeats exactly** in every run of the step; record the value.
2. **SkySite's refusals through `ReleaseBuild.file_hint`** (review F3): every `"...: run %s" % SKY_COMMAND` ending
   in `sky_site.gd` (`_check_written`, `_check_block`, and any other) becomes the reader pattern of the other
   readers: the problem text, then `ReleaseBuild.file_hint(SKY_COMMAND)` (outside a release: `; python -m mattini
   sky rebuilds it`; in one: `; it ships in the release's packs: download the release folder again`; read
   `release_build.gd` for the exact strings and join them as `surface_grid.gd` does). The logged `push_error` line
   keeps the form `SkySite: <path>: <problem>`. Update the live tests that assert the old ending
   (`test_m4_10_sky_site.gd`, `test_m4_08_fix_sky.gd`) to assert the new one, and add a test for both modes with
   `ReleaseBuild.set_exported_for_tests(true)` and `(false)`, restoring `null` afterwards. The census in
   `test_m4_08_release_hints.gd` (no script spells "rebuilds it" itself) must stay green; if it needs SkySite
   added to its behaviour list, add it.
3. **Words** (each a comment, docstring or doc line; no behaviour):
   - `game/tests/test_main_scene_terrain.gd` line 10: the main scene builds a sun and sky that follow the game's
     clock (briefs v0.4.0-04 to -09), not "a fixed sun".
   - `game/scripts/main.gd`: the file header's description of the scene (it still says "under the sun of the photo
     and a sky" and its list of blocks that open the panel omits the sky) says what the scene does now; the
     comment at the `FALLBACK_SUN_*` constants says the numbers were copied by hand from `config/shadows.json`
     (the flight's mean sun) and are the placeholder's only; the comment at the credits call (the line with
     `stars_drawn`) says the Hipparcos credit is shown whenever the star table is present and read, which is the
     licence's condition, not whenever stars are visible at that moment.
   - `pipeline/mattini/sky.py`: the module docstring's "Does NOT prove ... (test_m4_09_sky_config.py recomputes
     them ...)" sentence contradicts itself (review TG-11): make it say what is true (the step proves the config
     is well-formed and for this world; that its numbers are the village's is proved by the config test).
   - `game/scripts/sky/sky_clock.gd`: its header says the vectors cover 2020 to 2035 and nothing claims more; add
     that the game's day keys can leave that range and then the clock's output is unvalidated (review S-06, TG-10).
     Do not clamp anything.
4. **Not in this batch:** the stars table's presence in the export, a clamp of the clock, `night_sky`'s repeat
   mode, the moon's small terms, the sun placeholder tied to the config, the generator's test: the board's
   residue (`docs/reviews/v0.4.0-round1.md`).
