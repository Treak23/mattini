## Goal

A file transfer that swisstopo's host cuts short is named for what it is. Today
`download.urllib_fetch_file` streams the body to the part file and returns; Python's urllib ends a
body cut before its Content-Length without an error (brain.md H9), so the only sign is the
SHA-256 that does not match, and the refusal after the one retry says `SHA-256 … does not match
the published …`, which reads like a republished or damaged file. After this batch the fetcher
compares the bytes it wrote with the answer's Content-Length and raises a fetch error `cut at <N>
of <M> bytes`; the retry still runs, and when the last attempt was cut the refusal ends with the
advice `; a dropped connection heals on a rerun: run the command again`. Three refusals that work
today but had no test that could fail get one (the pinned file): `resolution_m` for swissimage and
swisssurface3d (I-04), the roofs step's inputs check before its provenance read (I-05) and the
surfaces config's per-cell SHA-256 values of another length (R2-S-01).

## Decisions already made

"(session)" is the release session of 0.5.0's (the go's answer A and the triage's readings of I-02,
I-04, I-05, R2-S-01); "(pin author)" a choice the pin author made while rehearsing, listed in the
PINSPEC's open questions for the session.

1. **A cut is a fetch error with its numbers** (session): `urllib_fetch_file` counts the bytes it
   writes to `dest` and, when the answer carried a Content-Length of digits and fewer bytes
   arrived, raises an exception that is an instance of one of `download.FETCH_ERRORS` (pin
   author: so `_fetch_verified`'s one retry catches it as it catches any fetch failure) whose text
   holds `cut at <bytes written> of <Content-Length> bytes` (rehearsal: `cut at 100 of 1295
   bytes`). An answer without a Content-Length (a body ended by closing the connection, or a
   chunked one) or with one that is not digits is not checked: it loads whole as before, and the
   SHA-256 still is (pinned: `test_a_body_of_no_announced_length_loads_unchecked`, a small server
   inside the pinned file; mutation rows 12 and 13). The rehearsal's shape (a free choice): a new `class CutTransfer(OSError)` beside
   `ResumeMismatch`, the copy loop written out (`while chunk := response.read(1 << 20)`, which made
   `shutil` unused there), the raise after the file is closed.
2. **The refusal's words** (session; pin author for "the last attempt"): `_fetch_verified`'s
   refusal stays `<where>: <url>: <problem> (after 2 attempts)`; when the last attempt's problem was
   a cut, `; a dropped connection heals on a rerun: run the command again` follows, so the whole
   line reads (rehearsal, photo tile 2623-1096): `mattini: error: tile 2623-1096 of area 'village':
   <url>: fetch failed: cut at 100 of 1295 bytes (after 2 attempts); a dropped connection heals on
   a rerun: run the command again`. A last attempt that ended otherwise (a whole body with another
   SHA-256, an HTTP 503) gets no hint, whatever the first attempt was.
3. **Where it applies:** every dataset fetched through `_fetch_verified` (terrain, buildings,
   photo, surface). The TLM file's resumable transfer (`urllib_fetch_range`, `download_tlm`) is
   unchanged: it already resumes a cut and checks the part's size (brief M3-03).
4. **I-04, test-only** (session): `load_datasets` refuses each of the three `RESOLUTION_DATASETS`
   (`swissalti3d`, `swissimage`, `swisssurface3d`) whose `resolution_m` is missing, `null`, a
   string, `0`, `0.0`, negative, `true`, `false`, a list, `Infinity` or `NaN`, with exactly
   `<path>: dataset '<name>': resolution_m must be a positive number of metres, found <repr>`
   (`found None` when missing); a whole number of metres (`2`) loads; the committed config's
   datasets without `resolution_m` are exactly swissbuildings3d and swisstlm3d; and through the
   command line (the harm M3-R1-I-04 reproduced was a KeyError traceback there) `python -m mattini
   lock photo|surface` and `download photo|surface` with swissimage's or swisssurface3d's
   `resolution_m` missing print exactly `mattini: error: <path>: dataset '<name>': resolution_m
   must be …, found None` on stderr, nothing on stdout, exit 1, the lock untouched. The code already
   does all this (rehearsal: the pinned cases pass on `main`); the pins make dropping a dataset from
   `RESOLUTION_DATASETS` fail (mutation row 7, which no existing test caught).
5. **I-05, test-only** (session): with no download at all (an empty raw folder, or one that does
   not exist) and a lock whose swissimage tile or swissbuildings3d sheet SHA-256 differs from what
   `config/roofs.json`'s `computed_for` was computed for, `build_roofs` refuses with design's step
   (`config/roofs.json`, `design recomputes`), never a download command or a provenance problem, with
   no progress line and nothing under the output folder. The code already does it; the pins make
   moving the inputs check after `_provenance_sheets` fail (row 9).
6. **R2-S-01, test-only** (session; 65 and 40 digits the pin author's): a value of

   be a SHA-256 in 64 lower-case hex characters, found '<value>'`; the committed config is accepted.
   The code already does it; the pins make a length range or a prefix `match` fail (rows 10, 11).
7. **One new test file** (pin author): the four items' tests live in one new pinned file,
