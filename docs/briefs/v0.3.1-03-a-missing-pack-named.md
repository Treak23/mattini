## Goal

In an exported build, a data pack that is missing is named in the log: which pack, the folder it
was looked for in, and what it holds ("the aerial photo", "the terrain's heights"). And every
reader's message about a missing or damaged generated file ends, in an exported build, with "it
ships in the release's packs: download the release folder again" instead of a pipeline command
(FB-005: with `mattini-photo.pck` moved aside, 0.3.0 logged only "the photo
res://assets/generated/photo/village.jpg is missing; python -m mattini photo rebuilds it").
Outside an export (the editor, the tests, a source checkout) every message stays as it is today.
A new static class, `ReleaseBuild`, answers "is this an exported build" for DataPacks and the
readers, and lets a test answer it.

Not this brief: `tools/export.sh` refusing packs that are not the expected ones (v0.3.1-04);
the missing packs shown on the error panel, and main.gd asking `ReleaseBuild` (v0.3.1-05); the
frame cap, the log flush and MSAA (v0.3.1-02, already landed); the far mountains' and the
capture mask's readers (`surroundings_grid.gd`, `shadow_grid.gd`), which a later release builds.

## Commands you will use

Keep every scratch file outside the worktree and give every Godot run you start yourself its
own `XDG_DATA_HOME` (H9; `tools/gate.sh` makes its own). **Your shell keeps no variables,
functions or working folder between tool calls**: create the scratch folder once (`mktemp -d`),
write its path down, and put that literal path wherever this brief writes `$S`; the same for
the base sha wherever it writes `$BASE`. A command run with an empty `$S` writes into `/`. Run
every command from your worktree's root; for the clean worktree of the batch gate, begin that
same call with `cd <its literal path> &&`.

One pinned script alone (`<script>` is the file name, for example
`test_m4_08_release_hints.gd`; call it "the single-script run" below):

```
XDG_DATA_HOME="$S/xdg" godot --headless --path game -s addons/gut/gut_cmdln.gd \
  -gtest=res://tests/<script> -gexit -gconfig= > "$S/<script>.log" 2>&1
```

Read a run by its lines, never by Godot's exit status (a script that does not load exits 0,
step 3): its `[Failed]` lines (GUT prints none for a passing test), its `<n>/<m> passed.` line,
its `---- ` summary and any `SCRIPT ERROR`, `ERROR` or `[ERROR]` line
(`grep -a -n -E '\[Failed\]|passed\.|SCRIPT ERROR|^ERROR|\[ERROR\]|Ignoring script|---- ' "$S/<script>.log"`).
GUT colours its lines in a raw log (an escape code stands before `---- `, `[Failed]` and
`[ERROR]`), so none of those three is anchored with `^`; Godot's own `ERROR` lines are not
coloured. After you add `release_build.gd`, run `XDG_DATA_HOME="$S/xdg" godot --headless --path game
--import` once before the next test run (H9: the class cache). Every import prints
`WARNING: ObjectDB instances leaked at exit (run with --verbose for details).`, on the base
